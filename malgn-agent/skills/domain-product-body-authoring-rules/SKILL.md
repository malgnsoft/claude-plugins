# Product Body Authoring Rules

## 정의

여기서 "제품 본문"은 **설치한 조직의 직원에게 그대로 전달되는 모든 자리**를 말한다 — `agents/*.md`, `skills/*/SKILL.md`, `knowledge/**/*.md`, 그리고 번들 `bin/`·`hooks/` 소스의 주석까지. 특히 훅이 각 프로젝트 CLAUDE.md에 인라인하는 본문은 **모든 세션에 물리는 가장 비싼 자리**다.

두 규칙의 뿌리는 같다: **설치 직원이 조회할 수 없는 것은 근거가 아니라 상시 비용이다.** 그들은 우리 기록 시스템도, 우리 회의도, 우리 커밋도 열어볼 수 없다.

## 1. 식별자를 근거로 달지 않는다

기록 시스템이 발급한 id(8자리 hex·26자 ULID 등), 커밋 해시, 로컬 auto-memory 키 — 어느 것도 설치 직원은 열어볼 수 없다.

- **교훈의 실질은 id가 아니라 문장으로 적는다.** 사유는 남기되 id는 붙이지 않는다.
- **범위 한정자로 쓰인 식별자는 지우기 전에 먼저 치환한다.** id가 근거가 아니라 "그 id가 가리키는 대상으로 범위를 좁히는" 용도로 쓰인 문장은, 서술형으로 바꿔 그 범위를 말로 표현한 뒤에 id를 뺀다. 기계적으로 밀면 문장이 가리키던 대상이 사라져 규칙이 무한정 열린다.
- 한 번 대량 제거한 뒤에도 다시 들어오면 그것은 결함이다.

## 2. 이력을 적지 않는다 — "지금 무엇이 참인가"만 적는다

**빼는 것**
- 합의·결정 날짜 도장
- 신설·정정 시점 표기
- 이관·폐기 경위("본문은 skills/X로 이관됐다", "구 모드 N은 폐기")
- 버전·라운드·커밋 언급

**남기는 것**
- **규칙이 생긴 이유(실패 양상)는 남긴다.** 이유를 지우면 에이전트가 규칙을 상황에 따라 흘려버린다. 단 시제를 현재형으로 바꾸고 날짜·주체·경위는 뺀다.
  - ❌ `판단 주체를 이전함 — 이전엔 구현자가 스스로 판단했으나 실패가 반복됐음`
  - ✅ `구현자가 착수 직전에 판단하면 안 부르고 넘어가는 일이 반복된다`
- **형식 예시 안의 날짜는 이력이 아니다.** 파일명 규칙(`review-auth-module-2025-07-10.md`), 캡처 기록 양식(`Viewport 1440×900, 2025-02-10`) 같은 서식은 그대로 둔다 — 날짜 모양이라고 기계적으로 밀면 예시가 망가진다.
- 외부 사실로서의 연도 표기(표준·규격 버전 등)도 대상이 아니다.

이력의 보관처는 프로젝트의 `STATUS.md`·`docs/archive/`·기록 시스템이지 제품 본문이 아니다.

## 3. 스코프는 형태가 아니라 목적으로 잡는다

기준은 **"설치 직원이 이 근거를 조회할 수 있는가"** 하나다. 디렉터리 이름도, 파일 확장자도, 백틱 같은 표기 형태도 기준이 아니다 — 그것들은 검색어일 뿐이다.

- `.md`만 훑으면 코드 주석에 남은 id가 그대로 통과한다.
- 백틱을 앵커로 잡으면 맨몸 id를 놓친다.
- **무언가를 스코프에서 제외할 때야말로 근거를 실물로 확인한다.** 제외 항목은 "괜찮다"는 도장을 받고 아무도 다시 열어보지 않아, 그렇게 살아남는다.

## 4. 검사 절차 (본문을 고친 뒤 그 자리에서)

malgn-agent 소스 루트에서 실행한다. 오탐(날짜·상수·해시가 아닌 16진 문자열)은 눈으로 걸러낸다 — 기계적으로 지우지 않는다.

```bash
# 식별자 후보 — 백틱 앵커 없이, 형태 무관으로 훑는다
grep -rnoE '\b[0-9a-f]{8}\b|\b01[0-9a-hjkmnp-tv-z]{24}\b' agents/ skills/ knowledge/ bin/ hooks/

# 커밋 해시·로컬 메모리 키를 근거로 단 표현
grep -rnE 'commit `[0-9a-f]{7,12}`|memory `[^`]+`' agents/ skills/ knowledge/ bin/ hooks/

# 이력 서술 후보 — 날짜 도장과 이관/폐기 경위
grep -rnE '[0-9]{4}-[0-9]{2}-[0-9]{2}|이관(됐|되었|함)|폐기(됨|했)|v[0-9]+\.[0-9]+' agents/ skills/ knowledge/
```

세 번째 명령은 형식 예시(파일명 규칙·캡처 양식)와 외부 규격 연도를 함께 잡으므로, 걸린 줄마다 §2의 "남기는 것"에 해당하는지 판정한 뒤에만 손댄다.

## 체크리스트

- [ ] 이번에 새로 쓴 본문에 조회 불가능한 식별자(기록 id·커밋 해시·메모리 키)가 없는가?
- [ ] 이력 서술(날짜 도장·신설/정정 시점·이관/폐기 경위·버전·라운드 언급)이 없는가?
- [ ] 규칙의 이유는 지우지 않고 남기되, 시제를 현재형으로 바꾸고 날짜·주체·경위는 뺐는가?
- [ ] 범위 한정자로 쓰인 식별자를 지웠다면, 그 범위를 서술형으로 먼저 치환했는가?
- [ ] 검사 범위에 `.md` 밖(번들 `bin/`·`hooks/` 주석)까지 포함했는가? 제외한 자리가 있다면 실물을 열어 확인했는가?
- [ ] 형식 예시 안의 날짜와 외부 규격 연도를 이력으로 오인해 지우지 않았는가?
