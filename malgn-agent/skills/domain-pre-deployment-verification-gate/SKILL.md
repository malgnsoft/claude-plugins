# 배포 전 로컬 검증 게이트

> 2026-07-23 대표+7에이전트 교차토론 합의. devops와 pm가 같은 내용을 서로 다른 지점에서 적용한다 — devops는 배포 작업 착수 전 자기검증으로, pm는 배포 논의가 제기되는 순간의 대화 게이트로.

## 3가지 확인 (모두 근거 첨부 — 근거 없으면 게이트 미통과)

1. **로컬 서버 실제 기동 + 로그 무오류**: 지금 이 순간 로컬 서버를 직접 띄우고(`pnpm run dev` 등), 콘솔/로그에 에러가 없는지 확인. 증거: 실행 로그 또는 스크린샷.
2. **핵심 플로우 1개 독립 재현**: QA 시나리오 표(`tests/test-report.md`)에서 **심각도(critical/blocker)가 가장 높은 시나리오를 지정해** devops 자신이 직접 클릭 또는 curl로 재현한다 — QA 결과를 그대로 재인용(재탕)하지 않고, 쉬운 시나리오를 임의로 골라 형식만 채우지도 않는다. 증거: 실행 커맨드+응답 또는 스크린샷 + 어느 시나리오를 골랐는지 명시.
3. **환경변수 실존 확인**: `.env.example`에 나열된 모든 키가 실제 로컬 `.env`에 값과 함께 존재하는지 대조. 증거: 누락 키 목록(없으면 "누락 없음" 명시).

## 게이트 미통과 시 행동

- **devops**: 위 3가지 중 하나라도 근거 없이 통과라고 적을 수 없다. 미통과면 배포 작업(Dockerfile/runbook 작성 등)을 시작하지 않고 QA로 반송한다. 자기검증 체크리스트에서도 이 근거 요구 수준을 그대로 유지한다 — "확인했는가"만 묻고 근거를 안 묻는 완화된 버전을 별도로 쓰지 않는다.
- **pm**: 배포 관련 논의(배포 시점·방식·서비스 여부)가 먼저 제기되면 — 그것이 "언제쯤 배포 가능할까요" 같은 순수 일정 질문이든 "지금 배포하자"는 실행 신호든 동일하게 — 위 3가지가 아니라 딱 한 질문으로 게이트를 연다: **"로컬에서 지금 이 상태로 직접 열어보셨는가?"** 아니오면 배포 논의 자체를 시작하지 않고 devops/qa-engineer에게 로컬 검증부터 요청한다. 예이고 근거(로그/스크린샷/커밋해시)가 있으면 그때 배포 논의를 진행한다.

## 근거 형식 예시

```
[게이트 통과 예시]
1. 로컬 서버: `pnpm run dev` 기동, 콘솔 에러 0건 (스크린샷: docs/shots/local-dev-ok.png)
2. 핵심 플로우: tests/test-report.md 중 severity=critical인 "결제→주문완료" 시나리오를 로그인→결제 curl로 재현, 200 OK 확인 (커밋 hash: a1b2c3d)
3. .env: .env.example 7개 키 중 7개 모두 로컬 .env에 값 존재, 누락 없음
```
