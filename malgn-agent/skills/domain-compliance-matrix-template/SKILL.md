# Compliance Matrix 작성 절차

Compliance Matrix는 rfp-analyst의 1차 산출물이다. **RFP의 모든 요구사항을 한 줄도 빠짐없이 추출해, 제안서의 어느 섹션/페이지가 그것에 답하는지 1:1로 매핑**하는 표. 이 표가 있으면 "요구했는데 빠진 항목"이 0이 되고, 평가위원이 채점할 때 "어디 보면 되는지"를 우리가 안내하게 된다. 누락 = 감점/실격이므로 제안의 안전벨트다.

## 1. 요구사항 추출 규칙

RFP/과업지시서/평가표를 **문장 단위로** 훑으며 요구를 뽑는다.
- **명령·의무 표현**을 신호로 잡는다: "~하여야 한다", "~포함할 것", "~제출", "필수", "이상/이내", "준수", SHALL/MUST.
- 한 문장에 요구가 여러 개면 **쪼갠다** (한 줄 = 한 요구 = 검증 가능 단위).
- 출처를 정확히 적는다(과업지시서 3.2.1, 평가표 항목 4, 제출서류 목록 7번 등) — 나중에 원문 대조용.
- 요구 유형을 태그: **[자격]**(참가자격·실적), **[기술]**(과업·방법론), **[관리]**(일정·보안·품질), **[양식]**(분량·서식·파일), **[서류]**(제출물), **[평가]**(배점 항목).

## 2. Compliance Matrix 표준 표

| Req-ID | 출처(RFP 위치) | 요구사항 (원문 요지) | 유형 | 평가배점 | 준수여부 | 대응 섹션/페이지 | 대응 근거(증거) | 책임자 | 비고/리스크 |
|--------|--------------|-------------------|------|---------|---------|----------------|---------------|--------|-----------|
| R-001 | 과업 3.2.1 | 무중단 데이터 이관 수행 | [기술] | 방법론 35점 | C | 3.2 이관방안 (p.24) | 5개교 무중단 실적 | writer | Win Theme 앵커 |
| R-002 | 제출서류 7 | ISMS 인증서 사본 제출 | [서류] | 가점 3점 | C | 별첨 A-3 | 인증서 원본 보유 | capture | 유효기간 확인필 |
| R-003 | 입찰공고 2 | SW사업자 신고 필 | [자격] | 자격(P/F) | C | — | 신고증 보유 | rfp-analyst | **실격요건** |
| R-004 | 평가표 5 | 본문 80p 이내 | [양식] | 감점 | C | 전체 | 78p | writer | 분량 모니터 |

### 준수여부(Compliance) 표기
- **C (Comply)**: 완전 충족 + 증거 있음
- **PC (Partial)**: 부분 충족 → 보완 필요 (리스크 칸에 무엇이 부족한지)
- **NC (Non-Comply)**: 미충족 → **즉시 에스컬레이션**. 자격/서류 NC면 Bid 재검토.
- **N/A**: 해당 없음 → **사유를 반드시 적는다** (빈칸 금지 — N/A에도 근거)

> 커버리지를 정량화한다: "전체 요구 42건 중 C 38 / PC 3 / NC 1 → 충족률 90%, NC 1건(R-017 지역업체 가점) 해소 필요." 이 한 줄을 capture/PM에 보고.

## 3. 평가표 배점 분석 (Compliance Matrix와 짝)

요구사항 매핑과 별도로, **배점표를 분석해 노력 배분 전략**을 만든다.

| 평가 대항목 | 배점 | 우리 강점도(1~5) | 노력 배분 | 담당 Win Theme |
|-----------|------|----------------|---------|--------------|
| 수행방법론 | 35 | 4 | ★★★ 최우선·페이지 집중 | WT-1 무중단 |
| 유사실적 | 25 | 5 | ★★ 실적표 강화 | WT-2 동종 다수 |
| 보안/품질 | 15 | 3 | ★★ 약점 보강 | WT-3 보안 |
| 가격 | 10 | 3 | finance 단가 전략 | — |

원칙: **배점 × 우리 약점도**가 큰 칸이 가장 위험 → 보강 우선. 배점 낮은 칸에 분량 낭비 금지.

## 4. 제출 전 실격방지 체크리스트 ★★★ (rfp-analyst 하드 게이트)

제출 직전, 아래가 **전부 ✅**가 되기 전엔 제출하지 않는다. 하나라도 ❌이면 제출 보류 + 에스컬레이션.

```
[ ] 입찰참가자격 충족 (면허·등록·업종) — 증빙 확인
[ ] 유사 실적요건 충족 (금액/건수/기간) — 실적증명서 확보
[ ] 제출서류 목록 전수 대조 — 단 하나도 누락 없음
    (사업자등록증/인감/사용인감계/청렴서약/보안서약/실적증명/인력경력 등)
[ ] 기술/가격 봉투(파일) 분리 — 기술파일에 가격정보 노출 0
[ ] 양식·분량·폰트·파일형식(HWP/PDF) RFP 규격 준수
[ ] 페이지 수 한도 이내 (목차/요약/별첨 포함 여부 확인)
[ ] 마감 시각 여유 확보 (마감 하루 전 제출 목표, 전자투찰 폭주 대비)
[ ] 가점요건 증빙 첨부 (중소/지역/인증 등 해당 시)
[ ] Compliance Matrix상 NC 0건 / PC 전부 해소
[ ] 오탈자·페이지번호·목차-본문 일치 최종 교정
[ ] (PT 있으면) 핵심인력 직접 발표 준비, 발표시간 한도 확인
```

## 5. 산출물 위치 / 협업

- 산출물: `~/workspace/[프로젝트명]/docs/proposal/compliance-matrix-[건명].md` (rfp-analyst 작성)
- 흐름: rfp-analyst가 Matrix 작성 → capture-strategist가 배점 분석으로 Win Theme 앵커링 → writer가 대응 섹션 집필 → reviewer(Red Team)가 Matrix로 누락 교차검증 → rfp-analyst가 제출 전 실격방지 게이트 최종 확인.
