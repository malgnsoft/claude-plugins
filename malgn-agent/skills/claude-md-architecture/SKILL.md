# CLAUDE.md 정보구조 — 배치·크기·리팩터링

> CLAUDE.md는 매 세션 전량 로드되는 **상시 비용**이다. 여기에 한 줄을 더하면 앞으로 열리는 모든 세션에 곱해져 물린다. 그래서 이 스킬의 주제는 "무엇을 잘 쓰나"가 아니라 **"무엇을 여기 남기고 무엇을 내보내나"**다.
> 사양 정본: https://code.claude.com/docs/en/memory

## 1. 배치 결정표 — 이 규칙을 어디에 적을까

| 자리 | 로드 시점 | 여기에 넣는 것 | 넣지 않는 것 |
|------|-----------|----------------|--------------|
| `CLAUDE.md` | 매 세션, 전량 | 매 세션 필요한 관례, 빌드·테스트 커맨드, "항상/절대 X" 규칙 | 절차서, 긴 참고자료, 특정 경로에서만 쓰는 지침 |
| `.claude/rules/*.md` | 매 세션(`paths` 없으면) 또는 매칭 파일을 읽을 때 | 언어·디렉터리 한정 지침(`paths` 프론트매터로 스코프) | 프로젝트 전역에 늘 필요한 규칙 |
| Skill | 호출하거나 관련 판단이 생겼을 때만 | 시점 트리거가 있는 절차·체크리스트, 도메인 판단기준, 긴 레퍼런스 | 매 순간 지켜야 하는 한 줄 규칙 |
| 훅 | 지정된 라이프사이클마다 실행 — 셸 명령뿐 아니라 HTTP 요청·MCP 도구 호출도 되고, 결정론적 규칙으로 안 되는 판단은 프롬프트·서브에이전트 방식으로 맡길 수 있다 | **반드시 강제돼야 하는 것**(차단·자동 실행) | 강제할 필요가 없는 권고 — 매번 걸리면 방해만 된다 |
| `CLAUDE.local.md`(gitignore) / 홈 디렉터리 `.claude/CLAUDE.md` | 매 세션, 본인만 | 개인 경로·샌드박스 URL·개인 취향 | 팀이 공유해야 할 규칙 |
| auto memory | 매 세션(색인만) | — 사람이 규칙을 배치하는 자리가 아니다(편집·삭제는 언제든 가능). 교정·선호는 Claude가 스스로 적는다 | 팀 규칙(그건 CLAUDE.md) |

**판정 3문** — 새 줄을 적기 전에 순서대로 답한다.

1. **매 세션 필요한가?** 아니면 rules(경로 한정)나 Skill(시점 한정)로 간다.
2. **어겨지면 안 되는가?** CLAUDE.md는 컨텍스트일 뿐 강제 설정이 아니다. 매번 반드시 실행·차단돼야 하는 것은 문장이 아니라 **훅**으로 쓴다.
3. **코드베이스에서 유도 가능한가?** 파일을 열면 그대로 나오는 것 — 디렉터리 나열, `package.json`을 옮겨 적은 의존성 목록, 코드를 훑으면 재구성되는 구조 개요 — 은 적지 않는다. 남길 것은 **함정, 규칙이 생긴 이유, 도구 기본값과 다른 관례**, 그리고 구조 중 **읽어도 모르는 것**(어느 디렉터리가 무슨 책임을 지는지, 왜 그렇게 나뉘었는지, 손대면 안 되는 곳이 어딘지)이다.
   - **구조를 적기로 했다면 낡지 않게 적는다.** 구조 서술을 경계하는 진짜 이유는 중복이 아니라 **확인되지 않는 서술은 반드시 코드와 갈라진다**는 것이다. 그래서 남기는 구조 서술 중 수치(파일 수·테이블 수·라우트 수 등)는 무엇을 세면 그 값이 나오는지까지 함께 적어 누구든 다시 셀 수 있게 둔다 — 적는 방법과 대조 시점은 Skill `project-standards` §6이 정본이다.
   - 판정은 **순차 누적**이다(하나를 통과했다고 끝나지 않는다): ① **판단(책임·이유·함정)을 담았나** → 담았으면 남긴다. ② 그렇게 남기기로 한 서술 **안에 수치가 있나** → 있으면 세는 대상까지 적는다. ③ 판단도 없고 다시 셀 수도 없는 나열이면 지운다. 판단과 수치가 한 줄에 함께 있는 경우가 가장 흔하므로(예: "`routes/` 12개 — 인증 미들웨어는 여기서만 붙인다"), ①에서 멈추면 그 수치가 확인되지 않은 채 남는다.

추가할 시점은 정해져 있다: 같은 실수가 두 번째 나올 때, 리뷰가 "알았어야 할 것"을 잡을 때, 지난 세션과 똑같은 교정을 또 타이핑할 때, 새 팀원이라면 똑같이 설명받아야 할 때.

`.claude/rules/`로 내보낼 때 `paths`는 글로브다(`src/**/*.{ts,tsx}` 같은 형태). **잘못된 패턴은 에러가 아니라 "아무것도 매칭하지 않음"으로 조용히 죽는다** — 중괄호 확장은 개수 예산이 있어 과하면 확장 없이 리터럴로 쓰이고, 대괄호는 문자 클래스로 해석되므로 파일명 속 `[`는 이스케이프해야 한다. 규칙을 옮긴 뒤 그 경로의 파일을 실제로 열어 규칙이 붙는지 확인한다.

## 2. 계층과 로드 순서

- 넓은 것 → 좁은 것 순으로 4계층이 있다: **관리정책(OS별 시스템 경로) → 사용자(홈 디렉터리 `.claude/CLAUDE.md`) → 프로젝트 `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` → 로컬 `./CLAUDE.local.md`**.
- **`.claude/rules/`는 이 계층 밖의 별도 축이 아니다.** `paths` 프론트매터가 없는 규칙은 시작 시 로드되고 **우선순위가 `.claude/CLAUDE.md`와 같다** — 프로젝트 계층과 동급이다. 사용자 계층(홈 디렉터리 `.claude/rules/`)은 프로젝트 규칙보다 **먼저** 로드돼, 프로젝트 규칙이 더 뒤에 와 **우선순위가 높다**(CLAUDE.md의 사용자→프로젝트 순서와 같은 방향). `paths`가 붙은 규칙만 시작 시가 아니라 매칭 파일을 읽을 때 들어온다.
- **덮어쓰기가 아니라 이어 붙이기다.** 디렉터리 트리에서는 루트 쪽이 먼저, 실행한 위치가 나중에 온다. 같은 디렉터리 안에서는 `CLAUDE.md` 뒤에 `CLAUDE.local.md`가 붙는다.
- 실행 위치 **하위** 디렉터리의 CLAUDE.md는 시작 시가 아니라 Claude가 그 디렉터리 파일을 읽을 때 들어온다.
- 계층 간 지시가 모순되면 Claude가 임의로 하나를 고른다 — 그래서 **정기적인 모순 제거가 규율**이다. 규칙에 예외가 있으면 예외까지 같은 자리에 적는다.
- 컴팩션 후 프로젝트 루트 CLAUDE.md는 디스크에서 다시 읽혀 재주입된다. 하위 CLAUDE.md와 `paths` 스코프 규칙은 해당 파일을 다시 만날 때까지 돌아오지 않는다 — 긴 세션에서 반드시 유지돼야 하는 규칙은 루트에 둔다.
- **서브에이전트(위임)에는 CLAUDE.md는 실리지만 메인 대화의 auto memory는 실리지 않는다**(내장 탐색·계획 에이전트는 둘 다 싣지 않는다). 위임받는 쪽이 반드시 알아야 하는 사실을 대화 중 메모에만 남기면 전달되지 않는다 — CLAUDE.md나 위임 지시서에 적는다.
- 모노레포에서 다른 팀 CLAUDE.md가 딸려 오면 `claudeMdExcludes` 설정(글로브)으로 배제한다. 단 관리정책 계층은 개인 설정으로 제외할 수 없다.
- `--add-dir`로 붙인 추가 디렉터리의 CLAUDE.md는 **기본적으로 로드되지 않는다**(전용 환경변수를 켜야 들어온다). 다른 저장소를 붙여 두고 "저쪽 규칙이 왜 안 먹지" 하는 오해가 여기서 나온다.
- 조직 전체에 깔아야 하는 지시는 관리정책 위치의 CLAUDE.md나 관리 설정의 `claudeMd` 키에 둔다. 다만 계층이 올라가도 성격은 그대로다 — **차단·강제는 설정(권한·샌드박스)의 일이고, CLAUDE.md는 어느 계층에서든 행동 안내일 뿐**이다.

## 3. `@import` 사양과 오용 방지

- 문법은 `@경로`다. **상대경로는 작업 디렉터리가 아니라 그 import를 적은 파일 기준**으로 풀린다. 절대경로도 된다. 임포트된 파일이 다시 import할 수 있고 최대 4홉까지다.
- 코드 스팬·펜스 블록 안은 파싱하지 않는다. 경로를 **언급만** 하려면 백틱으로 감싼다 — 맨몸으로 적으면 그 파일이 실제로 로드된다.
- **오용 ① — 컨텍스트를 아끼려고 분할한다.** import한 파일도 시작 시 함께 로드된다. 분할은 정리·재사용 수단이지 절감 수단이 아니다. 실제로 아끼려면 `.claude/rules/`(paths 스코프)나 Skill로 **옮겨야** 한다.
- **오용 ② — 팀이 공유하는 파일에 작업 디렉터리 밖 경로를 import한다.** 프로젝트 범위 파일이 바깥으로 해석되는 import를 담고 있으면 처음 만났을 때 승인 다이얼로그가 뜨고, 거절하면 그 import는 계속 비활성이며 다이얼로그도 다시 뜨지 않는다. 즉 **남의 PC에서 조용히 안 붙는다.** 팀 공유 CLAUDE.md에는 저장소 안 상대경로만 import한다(개인 절대경로·홈 경로 금지).
  - **그럼 작업 디렉터리 밖 내용이 정말 필요할 때는 어떻게 하나 — 관리 구역으로 인라인한다.** import를 포기하고 그 내용을 CLAUDE.md 본문에 직접 넣되, 손으로 복사한 사본은 원본이 바뀌어도 모른 채 갈라지므로 **기계가 소유·대조·교체할 수 있는 형태**로 넣는다: 시작·종료 마커로 감싸고, 시작 마커에 버전을 새기고, 재동기화 커맨드를 주석에 적는다. 마커와 주석은 HTML 주석이라 주입 전에 제거돼 토큰을 쓰지 않고, 사본이 낡으면 점검기가 버전 차이로 잡아낸다. 승인 다이얼로그라는 통제 불가능한 게이트에 전달을 맡기지 않는 것이 요점이다.
  - 도구가 심어 주는 구역이라면 그 도구의 절차로 넣고 손으로 만들지 않는다(예: PM 행동규율 블록은 Skill `project-standards` §9가 정본이다).
- 개인 지시는 `CLAUDE.local.md`에 두고 `.gitignore`에 넣는다. 다만 같은 저장소의 워크트리를 여러 개 쓰면 그 파일은 만든 워크트리에만 있다 — 여러 워크트리에서 공유하려면 홈 디렉터리 파일을 import한다(프로젝트 파일에서 홈 경로를 가리키면 외부 import라 최초 1회 승인 다이얼로그가 뜬다. 본인이 만든 것이면 승인하면 된다. 사용자 범위 파일 안의 import는 대체로 다이얼로그 없이 로드되지만, 일부 데스크톱 실행 환경은 작업 디렉터리 밖으로 나가는 import를 아예 건너뛴다).

## 4. 크기 규율

- **목표는 200줄 이하.** 길수록 컨텍스트를 먹고 지시 준수율이 떨어진다 — 크기는 미관 문제가 아니라 성능 문제다.
- **4 MiB를 넘으면 파일 전체가 로드되지 않는다.** 상한선이 아니라 벼랑이다(경고 없이 통째로 빠진다).
- **줄 수만 세지 말고 바이트도 잰다.** 줄 수는 서식에 따라 요동치는 지표이고, 실제로 물리는 것은 토큰이다. 토큰은 세션에서 셀 수 없지만 바이트는 셀 수 있다 — 한글은 UTF-8 3바이트/글자이고 **글자당 1토큰**을 넘지 않으므로, **바이트를 3으로 나눈 값이 한글 기준 토큰 수의 상한 근사치**다(ASCII가 섞일수록 여유가 생긴다).
  ```
  wc -c CLAUDE.md    # 바이트 — 실제 비용의 근사
  wc -l CLAUDE.md    # 줄 수 — 200 이하 목표
  ```
  PowerShell만 있는 환경이면 `(Get-Item CLAUDE.md).Length`로 바이트를 본다.
- **줄 단위 삭제 기준: "이 줄을 지우면 Claude가 실수하게 되는가?"** 아니면 뺀다.
- 빼는 것: 코드베이스를 읽으면 그대로 나오는 서술(§1 판정 3문 #3 — 판단을 담았거나 다시 셀 수 있게 적은 구조 서술은 남긴다), 조회할 수 없는 근거(사내 회의·티켓 번호·커밋 해시), 지나간 이력("예전엔 이랬다"). 남기는 것: 함정, 규칙이 생긴 이유, 기본값과 다른 관례.
- 사람 유지보수자용 메모는 **블록 HTML 주석**에 둔다 — 주입 전에 제거되어 토큰을 쓰지 않는다(코드블록 안 주석은 그대로 남는다).
- 문장은 검증 가능하게 쓴다: "포맷 잘 맞추기"가 아니라 "2칸 들여쓰기", "테스트 하기"가 아니라 "커밋 전 `<테스트 커맨드>` 실행".

## 5. 비파괴 리팩터링 5단계

**불변량: 규칙 개수는 줄지 않는다.** 옮기는 것이지 버리는 것이 아니다 — 줄 수가 줄었다는 사실 자체는 성공 근거가 아니다.

1. **실측** — `/context`를 열어 **Memory files**에 실제로 무엇이 로드됐는지 확인하고(있다고 믿은 파일이 안 붙어 있는 경우가 흔하다), 바이트·줄 수를 잰다.
2. **분류** — 각 항목에 §1 결정표의 자리를 하나씩 태그한다(매세션 / 경로한정 / 절차 / 강제 / 유도가능).
3. **이동** — 옮긴 자리에는 **한 줄 포인터만** 남긴다(예: "커밋 규약은 옮겨간 스킬 이름이 정본"). 원문을 복사해 두지 않는다 — 두 벌이 되면 반드시 갈라진다.
   - **예외: 기계가 대조·재동기화하는 관리 구역**(시작·종료 마커로 감싸고 버전을 새기고 점검 커맨드가 붙은 구간, §3). 여기서는 복제가 허용된다 — 갈라짐이 **감지되고 교정되기** 때문이다. 그러므로 관리 구역은 정리 대상이 아니다: "본문에 두 벌이 있다"며 걷어내면 도구가 심은 배선을 끊는다. 손대야 할 것 같으면 그 구역을 소유한 도구의 재동기화 절차로 돌린다. 예외는 그 점검 커맨드를 실제로 돌려 상태가 보고되는 구역에만 적용된다 — 마커 모양만 흉내 낸 구간은 예외가 아니라 그냥 두 벌이다.
4. **모순 제거** — 상위 디렉터리·하위 디렉터리·`.claude/rules/`·개인 파일까지 훑어 같은 주제의 상충 지시를 하나로 합친다.
5. **재검증** — `/context`로 옮긴 뒤에도 필요한 것이 로드되는지 다시 보고, 항목 목록을 전후 대조해 규칙 수 보존을 확인하고, 실제 작업 1건을 돌려 지시가 지켜지는지 관찰한다. **관찰 없이 "정리 완료"라고 보고하지 않는다.**

## 6. 진단

| 증상 | 확인 순서 |
|------|-----------|
| 지시가 안 지켜진다 | `/context` → **Memory files**에 그 파일이 있나. 없으면 위치·계층 문제(§2). 있으면 문장이 모호하거나 다른 파일과 모순(§1 판정 3문, §5-4) |
| 무엇이 언제 왜 로드됐는지 모르겠다 | `InstructionsLoaded` 훅으로 로드된 지시 파일을 로그로 남긴다 |
| 파일이 너무 크다 | `/doctor`가 체크인된 CLAUDE.md의 트림 후보를 제안한다(유도 가능한 내용은 깎고 함정·이유·관례는 남기는 기준). 제안은 그대로 받지 않는다 — **§1 기준으로 남기기로 한 구조 서술(판단을 담았거나 다시 셀 수 있게 적은 것)은 트림 후보로 올라와도 유지한다.** 단 **트림 점검은 Claude Code v2.1.206 이상에서만** 동작한다 — 구버전이라 제안이 안 나오면 §4·§5를 손으로 돌린다 |
| 어느 파일을 고쳐야 할지 모르겠다 | `/memory`로 계층별 파일 목록을 열어 편집한다 |
| 처음부터 만들어야 한다 | `/init`. 기존 CLAUDE.md가 있으면 덮어쓰지 않고 개선을 제안한다 |
| 이건 반드시 지켜져야 한다 | 문장으로는 보장되지 않는다 — CLAUDE.md는 시스템 프롬프트가 아니라 **사용자 메시지로 전달돼** 엄격 준수가 보장되지 않는다. 차단·자동 실행이 필요하면 훅으로 옮기고, 시스템 프롬프트 층위가 필요하면 `--append-system-prompt`로 올린다 |

## 7. AGENTS.md 상호운용

- **Claude Code는 `CLAUDE.md`를 읽고 `AGENTS.md`는 읽지 않는다.** 다른 코딩 에이전트용으로 `AGENTS.md`를 이미 쓰는 저장소라면, **`@AGENTS.md`를 import하는 `CLAUDE.md`를 만들고** 그 아래에 Claude 전용 지시를 덧붙인다. 내용을 양쪽에 복사하지 않는다.
  ```markdown
  @AGENTS.md

  ## Claude Code
  <Claude 전용 지시>
  ```
- Claude 전용 지시가 아예 없다면 심볼릭 링크(`ln -s AGENTS.md CLAUDE.md`)로도 된다. 다만 Windows에서는 심볼릭 링크 생성에 관리자 권한이나 개발자 모드가 필요하므로 **import 방식을 기본값**으로 삼는다.
- 어느 쪽이든 다음 세션에서 `/context`의 **Memory files**에 `CLAUDE.md`가 뜨는 것을 확인해야 끝난다.
