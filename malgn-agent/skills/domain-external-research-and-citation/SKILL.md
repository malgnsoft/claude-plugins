# External Research and Citation Skill

## Definition
외부 정보원(웹 검색, API, 공개 데이터)을 통해 최신 정보·수치·증거를 수집하고, 모든 주장에 출처를 명시하며, 근거 없는 단정을 배제하는 신뢰성 표준. 검색 결과 간 모순을 드러내고, 시간 경과 데이터의 최신성을 검증하여 팩트 체크 기반의 보고를 보증한다.

- **대상 에이전트:** capture-strategist, marketer, researcher
- **핵심 목표:** 외부 정보의 정확성·최신성·출처 추적성을 보증하고, 근거 없는 주장을 배제하며, 충돌하는 정보를 명시적으로 비교 분석하기

## Core Principles

### 1. 모든 주장에 출처 URL 명시 (Evidence-Based Citation)
- **검색 결과 인용:** `https://source-domain.com/path` + 수집 날짜 (예: "2026-07-10 검색")
- **수치 인용:** "X는 Y입니다" 다음에 반드시 `(출처: URL, 발표일/수집일)` 기입
  - ❌ "글로벌 시장은 5억 달러로 추정됩니다"
  - ✓ "글로벌 시장은 5억 달러로 추정됩니다 (Statista, 2025년 보고서, https://...)"
- **약자 사용 금지:** "가트너 보고서에 따르면" → "Gartner 2026 Magic Quadrant (https://gartner.com/...)"
- **스크린샷 첨부:** 수치가 시각 자료(표, 차트)인 경우 스크린샷 + URL 함께 제시

### 2. 근거 없는 단정 금지 (Unsubstantiated Claims Rejection)
- **검증 불가 표현 배제:**
  - ❌ "일반적으로 알려진 바에 따르면"
  - ❌ "대부분의 전문가들은 동의합니다"
  - ❌ "요즘 추세는"
- **인정된 불확실성:**
  - ✓ "X 발표 기관이 2026년 1월 발표한 보고서에 따르면" (기관명·일자·URL 명시)
  - ✓ "3개 소스(A, B, C) 중 2개가 동일 수치 보고" (차이 명시)
  - ✓ "정보 미확인 상태입니다 - 추가 조사 필요"
- **의견 vs 사실 구분:**
  - 사실적 주장: 반드시 출처 + 날짜
  - 해석/예상: "X 데이터를 보면 Y라고 해석할 수 있습니다 (데이터 출처: ...)"

### 3. 출처 충돌 드러내기 및 비교 분석 (Conflict Resolution and Comparison)
- **수치 불일치 명시:**
  - "A 소스: 시장규모 5억 달러 (2025년 Statista)"
  - "B 소스: 시장규모 4.8억 달러 (2025년 IDC)"
  - "→ 차이: ±4% (데이터 수집 시점·방법론 상이할 가능성)"
- **상충하는 주장:**
  - "X 발표: 성장률 15% (2026 전망)"
  - "Y 발표: 성장률 8% (2026 전망)"
  - "→ 편차 원인: 정의 차이(X는 전체 시장, Y는 코어 세그먼트) 또는 모형 차이"
- **시간에 따른 변화:**
  - "2024년 1월 보고서 vs. 2026년 1월 보고서 비교: 수치 변화 X% → Y%"
  - 변화의 원인 분석 또는 "원인 미파악, 추가 조사 필요" 명시
- **신뢰도 계층화:**
  - 🟢 **신뢰도 높음:** 공식 기관(정부·국제기구), 피어리뷰 학술지, 대형 분석사(Gartner, IDC, Forrester), 대규모 조사 (표본 500+)
  - 🟡 **중간:** 업계 매체, 대학 연구소, 언론 보도 (원출처 명시된 경우)
  - 🔴 **낮음:** 개별 블로그, 소셜 미디어, 원출처 미명시 기사
  - "→ 신뢰도 분석" 섹션에서 각 출처의 신뢰도 등급 명시

### 4. 시간 경과 데이터의 최신성 검증 (Temporal Freshness Check)
- **데이터 수집 날짜 기록:**
  - "2026-07-10 검색 기준" 명시 (보고서 발표일과 검색일 구분)
  - 예: "Forrester 2026년 Q1 보고서 (발표: 2026-04-15, 검색: 2026-07-10)"
- **유효 기간 평가:**
  - 실시간 데이터 (주가, 환율): "최종 업데이트: 2026-07-10 오후 3시"
  - 산업 리포트 (1년 단위): "2025년 발표 데이터, 현재(2026년 7월) 최신성 평가: 중간"
  - 장기 추세 (5년+): "해석: 트렌드는 유효, 수치는 보간 필요"
- **폐기 판정:**
  - 2년 이상 경과한 단기 예측 데이터: "⚠️ 발표된 지 2년 이상 경과 - 현재 상황 반영 여부 미확인"
  - 이유: 시장/정책/기술 변화로 인한 오래된 데이터의 신뢰도 저하
- **업데이트 체크:**
  - "동일 보고서의 최신 버전 확인: 2026년 버전은 미발표"
  - "X 통계의 월별 최신 버전: 2026-06 (07월은 미발표)"

### 5-1. 형제/유사 제품 혼입 방지 (Sibling/Similar Product Disambiguation)
- **문제**: 검색엔진 요약은 이름이 비슷한 형제/유사 제품(같은 회사의 다른 서비스, 유사 상호명의 다른 회사 등)의 정보를 섞어 반환할 수 있다.
- **적용 대상**: 외부 API/서비스의 정책·수치가 중요한 사실(데이터 보관기간·요금·인증 제한값·API 한도 등)을 인용할 때는 특히 취약하다.
- **행동 규칙**: WebSearch 요약만으로 결론 내리지 말고, 반드시 공식 문서 원문을 WebFetch로 열어 **대상 제품명·서비스명이 정확히 일치**하는지 재확인한다.
- **표기 규칙**: 원문 대조까지 마친 사실은 "확정된 사실"로, 요약만 확인한 정황은 "정황 증거(원문 미대조)"로 문서에서 명시적으로 구분한다.

### 5. 근거 검증 프로세스 (Claim-Evidence Verification Loop)
- **주장 제시 → 출처 수집 → 검증:**
  1. 주장 작성 (예: "글로벌 AI 시장은 2026년 500억 달러 규모로 성장할 것으로 예상")
  2. WebSearch로 최신 보고서 검색 (키워드: "global AI market size 2026 forecast")
  3. 상위 3-5개 소스 검색 및 WebFetch로 원문 확인
  4. 수치 추출 + 비교 분석 (다수 소스의 합의 여부)
  5. 신뢰도 판정 (기관 신뢰도 + 방법론 신뢰도 + 최신성)
  6. 최종 보고 (출처 URL + 수집일 + 신뢰도 등급 + 충돌 사항)
- **불일치 대응:**
  - 1-2개 소스만 찾은 경우: "제한된 검색 결과, 추가 확인 필요"
  - 3개 이상 소스 간 편차 > 20%: "상당한 편차 존재, 원인 분석 필요"
  - 출처가 서로를 인용하고 있는 경우: "연쇄 인용 구조 - 원출처 추적"

## Verification Checklist

### Research Scope and Planning
- [ ] 조사 목표 명시 (무엇을 찾을 것인가?)
- [ ] 키워드 및 검색 전략 기록
  - [ ] 1차 키워드 (기본 검색)
  - [ ] 2차 키워드 (정제/차별 검색)
  - [ ] 3차 키워드 (번역/유사어 검색)
- [ ] 정보원 다양성 확보 (학술·산업·뉴스·공식 기관 등)
- [ ] 지리적·시간적 범위 정의 (글로벌 vs 지역, 현재 vs 역사)

### Source Collection and Verification
- [ ] 각 검색 결과의 메타데이터 기록:
  - [ ] 출처 도메인 (신뢰도 평가용)
  - [ ] 발표 날짜 / 최근 업데이트 날짜
  - [ ] 저자/기관 (저명도 평가)
  - [ ] 원출처 여부 (직접 보고서 vs 기사화)
- [ ] WebFetch로 원문 확인 (기사 헤드라인만으로는 부족)
  - [ ] 수치·통계의 정확한 표현 확인
  - [ ] 데이터 수집 기간, 표본 크기, 방법론 확인
  - [ ] 주의 문구, 한계 명시 여부 확인
- [ ] **형제/유사 제품 혼입 체크**: 검색된 제품/서비스명이 대상과 정확히 일치하는가? (같은 회사의 다른 서비스, 유사 상호명 등으로 요약이 혼입되지 않았는지 원문 대조)
- [ ] 쌍방향 참조 체크 (연쇄 인용 추적)
  - [ ] "출처 A가 출처 B 인용" → B도 검증
  - [ ] "B가 C 원시 데이터 인용" → C도 추적 가능한가?

### Claim-Evidence Matching and Conflict Analysis
- [ ] 주장별 출처 매칭:
  - [ ] "X는 Y" → [URL1, URL2, URL3] (복수 출처 확보 권장)
  - [ ] 각 출처의 수치 일치 여부 확인
- [ ] 충돌 분석 (불일치 발생 시):
  - [ ] 수치 범위 통계화 (평균, 중앙값, 분산)
  - [ ] 편차 분석:
    - [ ] 데이터 수집 시점 차이?
    - [ ] 정의/범위 차이? (예: "산업 A만" vs "산업 A+B")
    - [ ] 방법론 차이? (조사 vs 모델 추정)
  - [ ] 신뢰도 비교 (어느 출처가 더 신뢰할 만한가?)
  - [ ] 최종 판정: "A 출처 채택 사유: ..." 또는 "범위로 제시: X ~ Y"
- [ ] 상충하는 주장 명시:
  - [ ] "발표A: 성장 15% vs. 발표B: 성장 8%"
  - [ ] 이유 추정 및 문서화

### Temporal Freshness and Validity Assessment
- [ ] 데이터 수집 기준 날짜 기록 (2026-07-10)
- [ ] 각 데이터의 발표/업데이트 일자 기록
- [ ] 시간 경과도 평가:
  - [ ] < 3개월: 🟢 매우 신선함
  - [ ] 3-6개월: 🟢 신선함
  - [ ] 6개월-1년: 🟡 중간 (변화 추적 권장)
  - [ ] 1-2년: 🟡 구식 (확인 필요)
  - [ ] 2년+: 🔴 오래됨 (재검토 강력 권장)
- [ ] 업데이트 가능성 체크:
  - [ ] "Q3 2026 보고서는 미발표"
  - [ ] "월간 통계 최신: 2026-06 (07월 미발표)"
- [ ] 장기 트렌드 vs 단기 수치 구분:
  - [ ] 단기(< 1년): 최신성 매우 중요
  - [ ] 장기(> 5년): 트렌드 방향만 유효, 수치는 참고용

### Citation Formatting and Traceability
- [ ] 모든 수치/주장에 URL 인용:
  - [ ] 형식: `(출처: [링크](URL), 발표일, 신뢰도)`
  - [ ] 예: `(출처: [Gartner 2026 AI Market Report](https://gartner.com/...), 발표: 2025-03-15, 신뢰도: 높음)`
- [ ] 약자 금지:
  - [ ] ❌ "가트너 보고서" → ✓ "Gartner 2026 Magic Quadrant"
  - [ ] ❌ "IDC 자료" → ✓ "IDC International Data Corporation, Worldwide AI Software Market 2026"
- [ ] 검색 날짜 일관성:
  - [ ] 모든 검색 결과에 수집 날짜 기록 (2026-07-10)
  - [ ] 다중 기간 검색 시: "2026-06-15 검색" vs "2026-07-10 검색" 구분
- [ ] 스크린샷/첨부물:
  - [ ] 핵심 수치가 시각 자료인 경우 스크린샷 첨부
  - [ ] 파일명에 출처 도메인+수집일 포함 (예: `gartner-ai-market-2026-07-10.png`)

### Source Credibility Assessment
- [ ] 기관 신뢰도:
  - [ ] 🟢 높음: 공식 기관(정부·국제기구 UN/World Bank), 피어리뷰 학술지, 대형 분석사(Gartner, IDC, Forrester)
  - [ ] 🟡 중간: 업계 매체, 대학 연구소, 신뢰 가능한 뉴스사
  - [ ] 🔴 낮음: 블로그, 소셜 미디어, 익명 소스, 출처 미명시
- [ ] 방법론 신뢰도:
  - [ ] 표본 크기 명시? (500+ 권장)
  - [ ] 수집 기간? (분기 이상 권장)
  - [ ] 재현 가능한가? (공개된 방법론)
- [ ] 이해관계 충돌 검토:
  - [ ] 제품 판매 기업의 시장 분석? (바이어스 가능성)
  - [ ] 중립적 제3자 분석인가?

### Unverified and Unsupported Claims Disclosure
- [ ] "다음은 검증되지 않았습니다" 명시:
  - [ ] 출처 부족 (단 1-2개 소스만 검색)
  - [ ] 데이터 오래됨 (1년 이상)
  - [ ] 관련 통계 미발견
- [ ] "다음은 추가 조사 필요" 명시:
  - [ ] 상충하는 주장 (조정 필요)
  - [ ] 신뢰도 낮은 소스 다수 (검증 필요)
  - [ ] 예상 데이터가 아직 미발표 (추적 예정)

### Contradiction and Reconciliation
- [ ] 충돌 분석 테이블:
  | 주장 | 소스 A | 소스 B | 소스 C | 평가 |
  |------|--------|--------|--------|------|
  | 시장규모 2026 | 500억$ | 480억$ | (미발견) | 편차 4%, 평균 490억$ |
- [ ] 각 충돌에 대해:
  - [ ] "원인: 데이터 범위 상이 (A는 전체, B는 코어만)"
  - [ ] "해석: 신뢰도 높은 A 채택"
  - [ ] 또는 "범위로 제시: 480-500억 달러"

### Quality Assurance Before Reporting
- [ ] 최종 검증:
  - [ ] 모든 URL이 유효한가? (WebFetch 확인)
  - [ ] 인용 수치가 원문과 일치하는가?
  - [ ] 수집 날짜가 일관되는가?
- [ ] 가독성 검토:
  - [ ] 출처 정보가 명확한가? (도메인만으로는 부족)
  - [ ] 신뢰도 등급이 명시되었는가?
  - [ ] 미확인 부분이 명시되었는가?
- [ ] 피드백 루프:
  - [ ] "이 수치는 확인이 필요하면 X 링크를 참조하세요"
  - [ ] "추가 정보는 댓글에 기록하시길 바랍니다"

## Integration Notes

- **마켓팅 보고서:** 경쟁사 시장 점유율, 산업 성장률, 신제품 출시 뉴스 - 모두 WebSearch + WebFetch로 출처 다중화
- **연구 논문:** 학술 데이터베이스(Google Scholar, 논문 DOI)의 피어리뷰 여부 확인, 인용 횟수 참고
- **경제/금융 통계:** 공식 기관(중앙은행, 통계청) 데이터 우선, 발표 주기(월/분기) 추적
