# 제안서 집필 원칙 (평가자 관점)

> writer가 제안서를 쓸 때의 핵심 원칙. 제안서는 "읽히는 글"이 아니라 **"채점되는 답안"**이다. 평가위원은 평가표를 들고 항목별 점수를 매긴다. 따라서 모든 문장은 "어느 평가항목에서 몇 점을 가져올 것인가"라는 질문에 답해야 한다. 일반 문서 작성(`writing/document-writing-guide.md`)과 달리, 제안서는 평가 메커니즘 자체를 공략한다.

## 1. 대전제 — 평가자는 우리 글을 "사랑"하지 않는다
- 평가위원은 수십 개 제안서를 짧은 시간에 채점한다. **찾기 쉽고, 근거가 분명하고, 점수 주기 편한** 제안서가 이긴다.
- "명문"은 가치가 없다. **평가표 항목에 1:1로 정렬되고 증거가 붙은 글**이 점수를 만든다.
- 우리 일: 평가위원이 채점표 칸을 채울 때 "여기 있네, 증거도 있네 → 만점" 하게 만드는 것.

## 2. Claim–Proof 구조 (모든 단락의 뼈대)
제안서의 모든 주장은 **주장(Claim) → 증거(Proof) → 이익(So-what)** 3박자로 쓴다.
```
Claim:  당사는 무중단 데이터 이관을 보장합니다.
Proof:  최근 3년 동종 대학 5개교를 다운타임 0분으로 이관했습니다(실적증명 별첨 A-2).
So-what: 따라서 귀 기관은 학사일정 차질 없이 신시스템으로 전환합니다.
```
- **증거 없는 Claim은 0점.** "최고", "최선", "풍부한 경험" 같은 형용사는 증거가 아니다 → 수치·실적·인증·사례·다이어그램으로 교체.
- 증거 유형 우선순위: 정량 실적(숫자) > 검증된 방법론/IP > 인증·특허 > 사례 > 정성 서술.

## 3. Action Caption / 핵심 메시지 — "제목이 점수를 판다"
평가위원은 본문보다 **제목·소제목·그림 캡션·표 제목**을 먼저(때로는 그것만) 본다.
- 소제목을 명사 나열("수행 방법론")이 아니라 **결론 문장(Action Caption)**으로: "동종 5개교 실적 기반 무중단 이관 방법론".
- 그림/표마다 **캡션에 결론**을 박는다: "[그림3] 단계별 병행운영으로 전환 리스크 제거 — 다운타임 0분".
- 평가위원이 캡션만 훑어도 우리 점수 논리가 전달되게 한다.

## 4. 평가항목별 증거 정렬 (Score-Box Filling)
rfp-analyst의 Compliance Matrix + 배점 분석을 받아, **각 평가항목 칸을 채울 증거를 그 항목 대응 섹션에 배치**한다.
- 섹션 머리에 "본 절은 평가항목 [수행방법론·35점]에 대응합니다"를 (명시 또는 암묵적으로) 정렬.
- **배점에 비례해 분량을 준다.** 35점 항목에 페이지를 몰고, 5점 항목은 간결하게. 배점표를 무시한 균등 분량은 비효율.
- 평가항목의 **평가 요소(세부 기준) 단어를 본문에 그대로 등장**시킨다("적정성", "구체성", "신기술 적용") — 평가위원이 채점 근거 단어를 찾기 쉽게.

## 5. Executive Summary (요약서) — 가장 공들일 1~2페이지
많은 평가위원이 요약서로 첫인상(과 때로는 점수 방향)을 정한다.
- 구성: ① 사업 이해(발주처 핵심 통점 한 줄) ② 핵심 제안 3~5개(= Win Theme) ③ 우리를 뽑아야 하는 이유(Discriminator) ④ 기대효과(수치).
- **발주처 언어로** 쓴다. 우리 자랑이 아니라 "당신의 문제를 이렇게 해결한다"로.
- Win Theme 3~5개를 여기서 선언하고, 본문 각 섹션이 그것을 증명하는 구조.
- 기업 제안이면 여기에 ROI 한 줄("9개월 내 투자비 회수")을 박는다.

## 6. 공공 사업수행계획서 vs 기업 ROI 제안 — 무엇이 다른가 ★

대표 결정(공공:기업=반반)에 따라 둘을 모두 능숙하게 쓴다. **독자와 승부처가 다르다.**

| 구분 | 공공 사업수행계획서 | 기업 제안서 |
|------|-------------------|-----------|
| 독자 | 평가위원(평가표로 채점, 감점 회피 성향) | 의사결정자(예산권자) + 실무자 |
| 승부처 | **평가표 점수 + 실격 회피** | **ROI 설득 + 신뢰** |
| 핵심 논리 | 과업 충실 이행·방법론·실적·관리(보안/품질) | 비용 절감·매출 증대·회수기간·리스크 감소 |
| 어조 | 객관·정량·규정 준수, 안정성 강조 | 비즈니스 가치·경쟁우위, 변화 후 모습 |
| 필수 요소 | 사업이해·방법론·WBS·보안·실적·조직·유지보수 | 현황 진단·해결방안·ROI 산식·도입효과·레퍼런스·가격 |
| 위험 관리 | 위험↔대응 표(정성+정성평가 대비) | 도입 리스크·전환 비용·실패 시 대안 |
| 승인 게이트 | 실격방지 체크(필수) | 가격·계약조건·도입 일정 합의 |

### 공공: "감점·실격을 0으로, 배점 높은 칸을 만점으로"
- 평가표 순서·언어로 목차 구성. 모든 요구에 응답(Compliance). 보안·품질·유지보수를 절대 빠뜨리지 않음(은근히 배점 큼).
- 위험관리·품질보증을 정량적으로(SLA 수치, QA 절차) 써서 "안정성" 점수 확보.

### 기업: "돈으로 증명하라"
- **ROI 산식을 명시**한다: `연 ROI = (연간 절감/증대액 − 연간 비용) / 투자비`, 회수기간(개월). 가정·산식·출처를 보여 신뢰 확보(finance 연계).
- As-Is(현황 통점, 수치화) → To-Be(도입 후, 수치화) → Gap을 우리가 메운다, 구조.
- 의사결정자용 1페이지 요약 + 실무자용 상세를 분리(독자 맞춤 톤, `writer.md`).

## 7. Ghosting을 글로 구현 (capture 전략을 문장으로)
capture-strategist가 정한 Ghosting 포인트를 본문에 자연스럽게 심는다.
- "본 사업은 [역량 X]가 없으면 [구체 리스크]가 발생합니다. 당사는 [X 실적/방법]으로 이를 보장합니다." — X가 경쟁사 약점일 때 효과적.
- **경쟁사 이름·비방은 절대 금지.** 사실에 근거해 "중요한 평가 기준"을 환기하는 데까지만.

## 8. 평범한 제안서를 넘는 자가검증 (제출 전)
`common/beyond-mediocre-output.md` + writer "평범함을 넘는 4대 기법"을 제안서용으로:
1. **복붙 테스트**: 발주처명만 바꿔 다른 입찰에 내도 말이 되면 → 고유성 0. 발주처 고유 통점·실제 실적 수치를 더 박는다.
2. **형용사 사냥**: "최고/최선/풍부한"을 전부 찾아 수치·실적으로 교체하거나 삭제.
3. **평가표 역추적**: 평가표를 펴고 "이 항목 점수는 본문 어디서 나오나"를 칸마다 짚는다. 안 짚이는 칸 = 점수 누락.
4. **So-what 점검**: 모든 주장에 "그래서 발주처가 얻는 것"이 붙었나.
5. **솔직한 경계**(기업 제안): 한계·전제를 숨기지 않고 대응책과 함께 — 신뢰를 만든다.

## 9. 협업 흐름
rfp-analyst(Compliance Matrix + 배점) → capture-strategist(Win Theme·Discriminator·Ghosting·Storyboard) → **writer(claim-proof로 평가표 정렬 집필)** → reviewer(Pink: 구조/정렬, Red: 평가표 모의채점) → writer 보강 → rfp-analyst(실격방지 게이트) → presenter(PT 슬라이드) → pm/finance(Gold/Green).
