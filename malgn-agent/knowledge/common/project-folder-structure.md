# 프로젝트 폴더 규칙 + 2단계 스킬 참조 구조

> 모든 프로젝트의 폴더 레이아웃과 에이전트 지식 참조 순서.

## 프로젝트 폴더 규칙

모든 프로젝트는 프로젝트 루트(`<workspace>/[프로젝트명]/`)에 생성한다.

```
<workspace>/[프로젝트명]/
├── README.md              # 프로젝트 개요
├── STATUS.md              # 진행 상태 단일 소스(실시간 업데이트) — progress.md 아님, 아래 참고
├── docs/                  # 기획서, 요구사항, 설계 문서
│   ├── [에이전트명]/       # 프로젝트 전용 스킬 문서
│   │   └── [스킬문서].md  # 이 프로젝트에만 필요한 전문 지식
│   ├── design/            # 디자인 산출물(와이어프레임·디자인시스템·스타일가이드)
│   ├── requirements.md
│   └── prd.md
├── src/                   # 소스 코드
├── output/                # 최종 결과물 (PPT, PDF 등)
└── tests/                 # 테스트
```

저장 규칙: 문서 산출물은 `docs/`, 소스코드는 `src/`, 디자인 산출물은 `docs/design/`, 최종 결과물(PPT/PDF)은 `output/`. PM은 위임 시 각 에이전트에게 정확한 저장 경로를 명시한다.

> **진행 상태 파일명**: 진행 상태의 단일 소스는 루트 `STATUS.md`다. 완료 항목은 1줄 요약만으로(id는 적지 않는다), 완료 섹션은 최근 3~5개만 유지하고 장기 이력은 malgnai-hub 조회로 넘긴다 — `progress.md`라는 파일명·"실시간 전체 로그 누적" 방식은 이 표준과 모순되므로 쓰지 않는다.

## 2단계 스킬 참조 구조

에이전트는 작업 시 아래 순서로 지식을 참조한다:

1. **공통 스킬** — 이 플러그인에 번들된 `knowledge/` (모든 프로젝트 공통)
2. **프로젝트 전용 스킬** — `docs/[에이전트명]/[스킬문서].md` (해당 프로젝트만)

프로젝트 전용 스킬 문서는 프로젝트의 도메인, 기술 스택, 비즈니스 규칙 등 해당 프로젝트에서만 필요한 전문 지식을 담는다.

예시:
```
docs/backend-dev/payment-api-guide.md    # 결제 API 연동 가이드
docs/frontend-dev/chart-library.md       # 차트 라이브러리 사용법
docs/security/compliance-rules.md        # 이 프로젝트의 컴플라이언스 규칙
```

프로젝트 시작 시 특수 도메인 지식이 필요하다고 판단되면, 해당 에이전트용 스킬 문서를 `docs/[에이전트명]/`에 미리 생성한다.
