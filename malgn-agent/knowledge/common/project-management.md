# 프로젝트 관리 베스트 프랙티스

> `progress.md`가 아니라 **`STATUS.md`가 진행 상태의 단일 소스**다. 정확한 파일 포맷(YAML frontmatter 필드, 부트스트랩 절차)은 `skills/project-standards`가 정본이며 여기서 다시 정의하지 않는다 — 이 문서는 그 표준을 실무에 적용할 때 필요한 배경 원칙(상태 추적 규율·품질 체크리스트·리스크 관리·ADR)만 다룬다.

## 상태 추적 원칙

1. **실시간 갱신**: 단계 시작/완료 시 즉시 `STATUS.md` 업데이트
2. **산출물 기록**: 생성된 파일 경로를 반드시 기록
3. **결정사항 기록**: 자율 판단한 내용은 malgnai-hub `decision_record`로 남기고, `STATUS.md`에는 요약만 유지
4. **완료 항목 정리**: 완료 섹션은 1줄 요약만으로 축약하고(id는 적지 않는다) 최근 3~5개만 유지(`skills/project-standards` §3과 동일 규칙 — 오래된 이력은 STATUS.md가 아니라 malgnai-hub 조회로 확인)
5. **재작업 이력**: 피드백으로 인한 수정은 별도 기록

## 품질 검토 체크리스트

### 산출물 공통
- [ ] 파일이 실제로 생성되었는가?
- [ ] 내용이 요구사항을 충족하는가?
- [ ] 이전 단계 산출물과 일관성이 있는가?
- [ ] 한국어 표현이 자연스러운가?

### 코드 산출물
- [ ] 실행 가능한가?
- [ ] TODO/플레이스홀더가 없는가?
- [ ] 에러 처리가 포함되어 있는가?
- [ ] README에 실행 방법이 명시되어 있는가?

## 리스크 관리

### 일반적 리스크 패턴
| 리스크 | 징후 | 대응 |
|--------|------|------|
| 요구사항 모호 | 기능 설명이 1줄 미만 | 유사 서비스 표준 참고하여 자율 결정 |
| 기술 스택 불일치 | 에이전트별 다른 기술 사용 | tech-stack.md를 단일 진실의 원천으로 |
| 산출물 누락 | 설명만 출력, 파일 미생성 | 반드시 Write 도구로 파일 생성 확인 |
| 컨텍스트 소실 | 대화 길어짐 | 이전 단계 문서를 직접 Read로 다시 읽기 |

## 의사결정 프레임워크 (ADR)

모호한 요구사항을 자율 결정할 때:

```markdown
### 결정: [결정 내용]
- **배경**: 왜 결정이 필요했는가
- **선택지**: 고려한 옵션들
- **결정**: 선택한 옵션과 이유
- **영향**: 이 결정이 미치는 범위
```
