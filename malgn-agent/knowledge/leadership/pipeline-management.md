# 5단계 파이프라인 관리

> `progress.md`가 아니라 **`STATUS.md`가 진행 상태의 단일 소스**다. 포맷/절차 정본은 `skills/project-standards`.

## 파이프라인 단계별 핵심

| 단계 | 산출물 | 핵심 체크포인트 |
|------|--------|---------------|
| 1. 요구사항 | requirements.md, prd.md | Must/Should/Nice 우선순위 명확한가? |
| 2. 아키텍처 | architecture.md, tech-stack.md, api-spec.md, data-model.md | 기술 선택 근거가 있는가? |
| 3. 구현 | src/ 전체 | 모든 API가 구현되었는가? TODO 없는가? |
| 4. 테스트 | tests/, test-report.md | 모든 테스트 통과하는가? |
| 5. 배포 | Dockerfile, docker-compose.yml, deploy-guide.md | 실제 실행 가능한가? |

## 단계 전환 조건

각 단계 완료 → 사용자 승인 → 다음 단계 진행

### 승인 요청 형식
```markdown
## N단계 완료: [단계명]

**생성된 파일**
- [파일 목록]

**주요 결정사항**
- [자율 결정한 내용]

**핵심 요약**
- [3~5줄]

승인하시면 다음 단계를 진행합니다.
피드백이 있으면 반영 후 재작성합니다.
```

## 피드백 처리 프로세스

1. 피드백 내용을 STATUS.md에 반영
2. 해당 단계 산출물 수정
3. 수정 내용 요약 후 재보고
4. 승인 → 다음 단계

## 중단/재개

- 중단: STATUS.md에 현재 상태 갱신
- 재개: STATUS.md 읽기 → 마지막 완료 단계 확인 → 다음 단계부터

## 병목 식별

| 병목 유형 | 증상 | 해결 |
|----------|------|------|
| 요구사항 불명확 | 기능 정의 모호 | 유사 서비스 참고하여 자율 결정 |
| 기술 스택 불일치 | 에이전트마다 다른 기술 | tech-stack.md를 기준으로 통일 |
| 코드 품질 미달 | 테스트 다수 실패 | 구현 에이전트 재호출 |
| 배포 설정 오류 | 컨테이너 실행 불가 | 기술 스택 재확인 |
