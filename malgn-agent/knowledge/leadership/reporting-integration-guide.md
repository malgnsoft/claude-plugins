# 보고서 통합 및 보고 가이드

> 출처: Venngage Executive Summary Guide, ProjectManager Stakeholder Reporting, Bold Reports Effective Reporting

## 보고서 통합 절차

PM이 여러 에이전트 산출물을 통합하여 사용자에게 보고하는 절차입니다.

### 단계 1: 산출물 수집
- 각 에이전트가 생성한 파일 목록 확인 (STATUS.md 산출물 섹션 참조, 세부 내역은 파일시스템 직접 확인)
- 누락 산출물이 있으면 해당 에이전트에 보완 요청

### 단계 2: 일관성 검증
- 에이전트 간 용어, 기술 스택, 범위가 일치하는지 확인
- 불일치 발견 시 선행 에이전트 산출물을 기준으로 통일

### 단계 3: 핵심 요약 생성
- 각 산출물에서 핵심 결과 3~5개 추출
- 사용자 관점에서 중요한 순서로 정렬

### 단계 4: 통합 보고서 작성

## 최종 보고서 템플릿

```markdown
# [프로젝트명] 완료 보고

## 요약
[1~2문장으로 프로젝트 결과 요약. RAG 상태 표시]

## 수행 내역
| 단계 | 에이전트 | 산출물 | 상태 |
|------|---------|--------|------|
| 조사 | researcher | docs/research.md | 완료 |
| 기획 | planner | docs/prd.md | 완료 |
| ... | ... | ... | ... |

## 주요 결과
1. [핵심 결과 1]
2. [핵심 결과 2]
3. [핵심 결과 3]

## 주요 결정사항
- [자율 결정 1]: [근거]
- [자율 결정 2]: [근거]

## 산출물 목록
- [파일 경로와 설명]

## 리스크 및 제한사항
- [식별된 리스크/한계]

## 다음 단계 (해당 시)
- [추가 작업이 필요한 경우]
```

## 중간 보고 (단계별)

각 파이프라인 단계 완료 시 간결하게 보고합니다:

```markdown
## N단계 완료: [단계명]

**상태**: 정상 / 주의 필요
**생성 파일**: [목록]
**주요 결정**: [자율 결정 사항]
**핵심 요약**: [3줄 이내]

승인하시면 다음 단계를 진행합니다.
```

## 보고 원칙

### 2분 규칙
보고서를 소리 내어 읽었을 때 2분 이내에 끝나야 합니다. 넘으면 줄여야 합니다.

### 계층적 구조
1. **제목/요약** (10초): 프로젝트 상태를 한눈에
2. **주요 결과** (30초): 핵심 성과와 결정 사항
3. **상세 내역** (필요 시): 산출물 목록, 리스크, 다음 단계

### 명확한 책임
- 모든 다음 단계 항목에는 담당 에이전트를 명시
- "검토 필요" 같은 모호한 표현 대신 "security 에이전트가 보안 점검 수행" 처럼 구체적으로

### RAG 상태 표시
- **Green**: 정상 진행, 일정 내 완료 예상
- **Amber**: 주의 필요, 리스크 있으나 대응 가능
- **Red**: 심각한 문제, 사용자 개입 필요
