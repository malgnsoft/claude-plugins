# 1. 훈련 시스템 개요 및 철학

## 1.1 목적과 목표

맑은AI 에이전트 시스템(19명)은 단순히 명령을 실행하는 도구가 아니라 **역할별 전문성을 가진 AI 협업 팀**이다. 이 훈련 가이드는 다음을 목적으로 한다:

- **에이전트 역량을 측정 가능하게**: 스킬 점수·경험 점수로 객관화
- **학습을 지속 가능하게**: 프로젝트마다 교훈을 축적해 다음 프로젝트에서 더 잘한다
- **산출물 품질을 높이게**: "MD가 잘 쓰여 있나"가 아니라 "실제로 잘 해내는가"를 기준으로

**목표:**
- 에이전트별 최종 점수 70점 이상 유지
- 프로젝트 재작업률 20% 미만
- 신규 에이전트 온보딩 시간 2시간 이내

## 1.2 핵심 원칙

### 원칙 1: 산출물 기반 진단

MD 키워드 점수는 보조 지표다. 에이전트가 **실제로 만든 것**이 기준이다.
"리뷰 보고서가 프로젝트명만 바꾸면 다른 데 붙일 수 있는가?" 이 질문에 YES면 약한 산출물이다.
진단할 때 항상 실제 산출물 파일을 열어 읽는다.

### 원칙 2: 지속적 학습

한 번 가르치고 끝이 아니다. 매 프로젝트 회고 후 교훈을 에이전트 MD와 knowledge에 반영한다.
이미 반영한 교훈은 중복 반영하지 않도록 학습 보고서로 추적한다.

### 원칙 3: 최소 MD, 최대 Knowledge

MD는 역할 정체성과 원칙만 담는다. 상세 절차·예시·체크리스트는 knowledge 파일에 두고 경로로 참조한다.
MD가 짧을수록 세션 로드 비용이 낮다. Knowledge가 깊을수록 실제 품질이 높다.

### 원칙 4: 토큰 효율은 상시 기준

새 지침을 MD에 추가할 때마다 "이 지침이 턴·토큰을 늘리지 않는가"를 확인한다.
모든 에이전트에 자기중단·압축 반환·(리더형) 서브 감독 3종이 박제되어 있어야 한다.

### 원칙 5: 교훈 일반화 게이트

단일 사례에서 얻은 교훈을 영구 규칙으로 올리기 전, 4부 구조(전제조건/권장행동/반례/판별질문)를 채워야 한다.
"항상/무조건/절대" 단정형 규칙은 반려. 반례 검토를 마친 경우에만 예외.

# 2. 에이전트 MD 표준 포맷

## 2.1 포맷 구조

모든 에이전트 MD는 아래 7개 섹션으로 구성된다. 섹션 순서는 고정.

```
# [에이전트명] ([직함])
헤더 — 역할 1줄, 팀, 모델, 점수 태그

## 핵심 원칙
행동 원칙 5개 이내

## 스킬 정의
스킬 테이블 (배점 합산 100점)

## 경험 이력
프로젝트 경험 + 소소한 학습 이력

## 지식 참조
knowledge 파일 경로 목록

## 금지 사항 및 승인 필요 작업
금지/승인 목록

## 토큰 효율
자기중단·압축반환·(리더형) 서브감독
```

상세 포맷: `이 플러그인의 knowledge/leadership/agent-md-format-standard.md`

## 2.2 포맷 예시 — architect

```markdown
# architect (시스템 아키텍트)

**역할**: PRD를 받아 시스템 구조·API 명세·데이터 모델을 설계하고 개발팀에 전달
**팀**: 개발팀 | **모델**: opus
<!-- skill_score: 76/100 exp_score: 45/100 total: 70/100 -->
<!-- last_trained: 2026-07-09 -->

---

## 핵심 원칙

1. 설계 결정에는 반드시 트레이드오프 근거를 명시한다 (왜 이 기술을 선택했나).
2. API 경로는 버전(/v1/)을 포함한다. 버전 없는 경로는 설계 결함이다.
3. 데이터 모델은 ERD + 인덱스 전략까지 포함해야 완성으로 본다.
4. 확장성 설계는 개념이 아니라 구체적 패턴(어떤 캐시, 어떤 큐)으로 명시한다.
5. 보안 아키텍처는 인증/인가 흐름도가 없으면 미완성이다.
```

# 3. 스킬 정의 및 점수 체계

## 3.1 스킬 점수 계산

```
스킬 원점수 = Σ(각 스킬의 level × 해당 스킬 배점/5)
```

**level 산정**: `node bin/sync-agents.js` — MD 키워드 매칭으로 1~5점 자동 계산
- 5점: 전용 섹션 + 깊은 빈도 + 근접 디테일 모두 충족
- 4점: 대부분 충족, 한 축 부족
- 3점: 다뤄지긴 하나 깊이/전용성 부족
- 2점: 언급 수준
- 1점: 사실상 미커버

**예시**:
- 스킬A(배점 25점), level=4 → 20점
- 스킬B(배점 20점), level=5 → 20점
- 스킬C(배점 20점), level=3 → 12점
- 스킬 원점수 = 20+20+12+... (전 스킬 합산)

## 3.2 경험 점수 적립

| 이벤트 | 점수 |
|--------|------|
| 프로젝트 완료 참여 | +5점 |
| 재작업 없이 1회 통과 | +3점 |
| 리뷰어 Critical 0건 | +2점 |
| 소소한 학습 이력 추가 | +1점/건 |
| 재작업 발생 | -2점 |

적립 방법:
1. 프로젝트 완료 후 PM이 trainer에게 "경험 점수 갱신" 지시
2. Trainer가 해당 에이전트 MD의 경험 이력 섹션에 행 추가
3. malgnai-mcp `agent_learning_log_add`로 이력 기록

## 3.3 최종 점수 공식

```
최종점수 = 스킬점수 × 0.8 + 경험점수 × 0.2
```

**등급**:
- 90~100: S급 (벤치마크)
- 80~89: A급 (우수)
- 70~79: B급 (양호 — 목표 기준선)
- 60~69: C급 (개선 필요)
- 60 미만: D급 (집중 학습 대상)

# 4. 지식 문서(knowledge) 관리 체계

## 4.1 knowledge 폴더 구조

```
knowledge/  (이 플러그인 기준 상대 경로)
├── common/          ← 전체 공통 (token-efficient, beyond-mediocre 등)
├── leadership/      ← pm, trainer
├── planning/        ← planner, researcher
├── proposal/        ← capture-strategist, rfp-analyst
├── finance/         ← finance
├── marketing/       ← marketer
├── design/          ← ux-designer, visual-designer
├── architecture/    ← architect
├── backend/         ← backend-dev
├── frontend/        ← frontend-dev
├── quality/         ← qa-engineer
├── security/        ← security
├── devops/          ← devops
├── writing/         ← writer
├── presentation/    ← presenter
├── review/          ← reviewer (재사용 페르소나 자산)
└── lessons/         ← 프로젝트 회고 교훈
```

## 4.2 스킬별 지식 문서 작성 기준

**좋은 knowledge 파일의 4요소:**
1. **문제 상황**: 어떤 상황에서 이 문서를 읽어야 하는가
2. **핵심 원칙**: 이 스킬의 본질적 판단 기준
3. **구체적 패턴**: 실제로 적용할 수 있는 절차·예시·체크리스트
4. **반례/주의**: 이 문서가 틀리는 경우

**금지 패턴:**
- 추상적 개념만 나열 ("중요하다", "고려해야 한다")
- 출처 없는 권고
- 모든 상황에 다 맞는 범용 조언 (케바케로 끝나는 문서)

## 4.3 지식 문서 업데이트 주기

| 트리거 | 액션 |
|--------|------|
| 프로젝트 완료 후 회고 | lessons/[프로젝트명].md 작성 |
| 에이전트 산출물 약점 발견 | 해당 에이전트 knowledge 보강 |
| 외부 베스트 프랙티스 수집 | 해당 폴더 knowledge 추가 |
| MD 최적화 (모드 8) | 분기 1회 — 수동 트리거 |

## 4.4 교훈 일반화 게이트 (4부 구조)

단일 사례에서 얻은 교훈을 영구 규칙으로 올리기 전 필수 통과:

```
전제조건  : 이 교훈이 적용되는 상황 (X한 경우에 한해)
권장 행동  : 그래서 Y하라
반례/예외  : 이 교훈이 틀리는 경우 최소 1개
판별 질문  : 적용자가 갈림길에서 던질 질문 1~2개 → 각 답에 명확한 행동
```

**실제 교정 사례:**
- 나쁨: "화면 분류는 무조건 데이터 group-by" (전칭, 반려)
- 좋음: "분류가 자주 변동하고 권위 출처가 데이터면 group-by, 닫혀 있고 정책/스키마가 권위면 명시 등록 — 판별: 6개월 뒤 분류가 늘 수 있나?"

# 5. 훈련 실행 절차

## 5.1 개별 에이전트 훈련 (모드 1)

**트리거**: "[에이전트명] 스킬업 시켜줘"

1. 해당 에이전트 MD 읽기
2. 스킬 점수 확인 (`node bin/sync-agents.js`)
3. 관련 knowledge 파일 읽기
4. 취약 스킬 분석 → 산출물 진단 병행
5. WebSearch로 최신 자료 수집
6. knowledge 파일 보강
7. 에이전트 MD 보강 (토큰 규율 점검 포함)
8. malgnai-mcp `agent_learning_log_add` 기록

**소요 시간**: 30~60분/에이전트

## 5.2 전원 훈련 (모드 2)

**트리거**: "전원 학습시켜"

1. 전체 19개 에이전트 스킬 현황 분석 (sync-agents.js)
2. 팀별 공통 취약 영역 식별
3. common/ knowledge 먼저 보강
4. 팀별 → 개별 에이전트 순으로 보강
5. 에이전트마다 malgnai-mcp 기록
6. 전체 결과 보고

**소요 시간**: 3~6시간

## 5.3 산출물 기반 진단 (모드 7) ★가장 강력

**트리거**: "리뷰가 너무 평범해", "[에이전트] 결과물 수준 올려줘"

1. 해당 에이전트 실제 산출물 파일 수집 (산출물 위치 맵 참조)
2. `common/beyond-mediocre-output.md`의 5가지 냄새로 1차 스캔
3. 역할별 기준으로 정밀 진단, 약점 인용 포함 기록
4. 근본 원인을 MD/knowledge 구조 결함에서 찾기
5. 처방을 에이전트 MD 또는 knowledge에 박제
6. before/after 산출물 인용으로 보고

**핵심**: 모드 1은 "MD가 잘 쓰여 있나", 모드 7은 "실제로 잘 해내는가"

## 5.4 MD 최적화 (모드 8) — 수동 전용

**트리거**: "MD 정리해줘", "찌꺼기 청소", "MD 최적화" (수동 요청에만 반응, 자동 트리거 금지)

**대원칙**: 비파괴. 교훈 내용은 1:1 보존, 표현과 구조만 압축.

1. 대상 에이전트 MD 통독
2. 중복 지침, 모순, 죽은 참조, n=1 찌꺼기 식별
3. lessons↔MD 일관성 점검
4. 비파괴 압축 적용
5. before/after 보고 (교훈 수 손실 0 증명)

# 7. 에이전트 MD 갱신 절차

## 7.1 기존 에이전트 백업

**필수 선행 단계**:
```bash
cp -r ~/.claude/agents ~/.claude/agents_backup_$(date +%Y%m%d)
```

백업 경로: `~/.claude/agents_backup_YYYYMMDD/`

## 7.2 새 포맷으로 마이그레이션

**순서**:
1. 백업 확인
2. 기존 MD 읽기 → 담긴 교훈 목록 추출

```
Before: [교훈A, 교훈B, 교훈C, ...]
After: [교훈A, 교훈B, 교훈C, ...]  ← 동일 개수, 동일 내용
```
