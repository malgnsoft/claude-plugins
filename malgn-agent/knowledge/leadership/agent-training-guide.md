# 1장. 훈련 시스템 개요 및 철학

## 1.1 목적과 목표

맑은AI 에이전트 시스템(현재 21종)은 역할별 전문성을 가진 AI 협업 팀이다. 이 훈련 가이드는 다음 세 가지를 달성하기 위해 존재한다.

- **역량을 측정 가능하게**: 스킬 점수·경험 점수로 객관화하여 "느낌"이 아닌 수치로 관리
- **학습을 지속 가능하게**: 매 프로젝트마다 교훈을 축적해 다음 프로젝트에서 반복 실수를 제거
- **산출물 품질을 높이게**: "MD가 잘 쓰여 있나"가 아니라 "실제로 잘 해내는가"를 기준으로

**정량 목표:**

| 지표 | 목표 |
|------|------|
| 에이전트별 최종 점수 | 70점 이상 (B급 이상) 유지 |
| 프로젝트 재작업률 | 20% 미만 |
| 신규 에이전트 온보딩 | 2시간 이내 |

## 1.2 핵심 원칙 5가지

> **원칙 1: 산출물 기반 진단**
> MD 키워드 점수는 보조 지표다. 에이전트가 실제로 만든 것이 기준이다.
> "리뷰 보고서가 프로젝트명만 바꾸면 다른 데 붙일 수 있는가?" — YES면 약한 산출물이다.
> 진단할 때 항상 실제 산출물 파일을 열어 읽는다.
> (진단·채점의 **실행 주체는 evaluator**다. trainer는 그 개선안을 MD/knowledge에 반영한다 — 5장)

> **원칙 2: 지속적 학습**
> 한 번 가르치고 끝이 아니다. 매 프로젝트 회고 후 교훈을 MD와 knowledge에 반영한다.
> 이미 반영한 교훈은 중복 반영하지 않도록 학습 보고서로 추적한다.

> **원칙 3: 최소 MD, 최대 Knowledge**
> MD는 역할 정체성과 원칙만 담는다. 상세 절차·예시·체크리스트는 knowledge 파일에 위임한다.
> MD가 짧을수록 세션 로드 비용이 낮다. Knowledge가 깊을수록 실제 품질이 높다.

> **원칙 4: 토큰 효율은 상시 기준**
> 새 지침을 MD에 추가할 때마다 "이 지침이 턴·토큰을 늘리지 않는가"를 확인한다.
> 모든 에이전트에 자기중단·압축 반환·(리더형) 서브 감독 3종이 박제되어 있어야 한다.

> **원칙 5: 교훈 일반화 게이트**
> 단일 사례에서 얻은 교훈을 영구 규칙으로 올리기 전, 4부 구조(전제조건/권장행동/반례/판별질문)를 채워야 한다.
> "항상/무조건/절대" 단정형 규칙은 반려. 반례 검토를 마친 경우에만 예외.

**핵심 요약**: "MD 키워드가 아닌 실제 산출물로, 매 프로젝트마다, 교훈을 게이트 통과 후 지식으로 쌓는다."

# 2장. 에이전트 MD 표준 포맷

## 2.1 포맷 철학

**최소 MD, 최대 Knowledge.** MD는 역할 정체성·원칙·토큰 규율·knowledge 경로만 담는다. 스킬 상세·절차·예시·체크리스트는 knowledge 파일에 위임하고 MD에서 경로로 참조한다. MD가 짧을수록 세션 로드 비용이 낮고, knowledge가 풍부할수록 실제 품질이 높다.

## 2.2 9단 골격 (MD 골격 정본)

모든 에이전트 MD는 아래 9단으로 구성된다. 순서는 고정이다(부록의 요약 표와 동일한 골격이다).

| 단 | 섹션 | 내용 | 주의사항 |
|----|------|------|---------|
| 1 | frontmatter + 역할 선언 | `name` / `description` / `tools` / `model` + 본문 첫 줄의 역할 1문장 | `description`은 "무엇을 만들어 누구에게 전달하는가"를 동사로 쓰고, **언제 호출하고 언제 생략하는지**까지 담는다(PM의 위임 판단 근거가 된다) |
| 2 | `## 핵심 원칙` | 행동 원칙 5개 이내 | 추상 형용사 금지, 관찰 가능한 행동만 |
| 3 | `## 역할 경계` | 호출자 / 범위 / 인접 경계 / 승인 권한 | 금지 사항과 승인 필요 작업도 여기에 적는다(별도 섹션을 만들지 않는다). 스킬 정의 파일(`skill-definitions.js` EMPLOYEE_CARDS)이 있는 운영 환경이면 그것과 동기화(미번들 — 없으면 각 에이전트 MD를 직접 대조) |
| 4 | `## 스킬 상세` | 그 역할의 판단 기준·절차 | 상세 절차·예시·체크리스트는 Skill/knowledge로 위임하고 경로만 참조(§2.1) |
| 5 | `## 전제 조건` | 작업 전 반드시 읽어야 할 파일·선행 조건 | 파일 경로는 실재하는 것만. 없으면 "없으면 어떻게 하라"까지 적는다 |
| 6 | `## 자기 검증` | 보고 전 확인할 체크박스 | 실물 대조로 참·거짓이 갈리는 항목만. "잘 했는가" 류 자문은 금지 |
| 7 | `## 산출물` | 산출 파일별 소제목 + 담을 내용 | 경로를 명시한다. 파일로 남지 않는 산출물은 산출물이 아니다 |
| 8 | `## 학습 자료` | **필수(작업 전 항상 참조) / 참고(상황별 확인)** 2단 | 파일 없으면 경로 추가 전 파일 먼저 생성. 상황별 항목은 `**[상황: …]**`으로 조건을 앞세운다 |
| 9 | `## 토큰 효율` | 자기중단·압축반환·(리더형) 서브감독 | 리더형은 서브 감독 항목 반드시 포함. 상세는 Skill `common-token-efficient-collaboration`에 위임 |

> **MD에 두지 않는 것**: 스킬 배점표·점수 태그·`last_trained` 같은 계측값(→ 3장), 프로젝트 경험·학습 이력(→ 6장, malgnai-hub `agent_learning_record`가 정본). 9단 골격에는 이력 섹션이 없다 — 학습의 결과로 MD에 남는 것은 이력이 아니라 **규칙**이며, 현재형으로 적는다.

## 2.4 MD 신규 작성·재작성 절차

새 에이전트 MD를 쓸 때, 그리고 9단 골격을 따르지 않는 MD를 넘겨받았을 때 적용한다.

2. 기존 MD에서 교훈 목록 추출 (손실 없이)
3. §2.2의 9단 골격으로 재작성 — 순서 고정, 실물 예시는 §2.3
4. 교훈 목록 대조 — 누락 0 확인
5. 금지·승인 항목을 `## 역할 경계`에 반영. 스킬 정의 파일(`skill-definitions.js` EMPLOYEE_CARDS)이 있는 운영 환경이면 그것과 동기화(미번들 — 없으면 각 에이전트 MD를 직접 대조)

# 3장. 스킬 정의 및 점수 체계

## 3.1 스킬 점수 계산

**자동 측정 명령**: `node bin/sync-agents.js`(이 스크립트는 이 플러그인에 번들되지 않음 — 운영 프로젝트에 구축되어 있다면 그 경로를 사용, 없으면 수동 산정)

MD 키워드를 스캔해 스킬별 level(1~5)을 자동 계산한다.

| Level | 기준 |
|-------|------|
| 5 | 전용 섹션 + 높은 빈도 + 깊은 디테일 모두 충족 |
| 4 | 대부분 충족, 한 축 부족 |
| 3 | 다뤄지긴 하나 깊이/전용성 부족 |
| 2 | 언급 수준 |
| 1 | 사실상 미커버 |

**환산 공식**:
```
스킬 원점수 = Σ(각 스킬의 level × 배점/5)

예시: 스킬A(배점 25점, level=4) → 20점
     스킬B(배점 20점, level=5) → 20점
     스킬C(배점 20점, level=3) → 12점
```

**배점 원칙**: 배점(합산 100점)은 균등 분배가 아니라 **그 역할의 핵심 가치에 비례해 차등 부여**한다.

**보관 위치**: 배점표·점수는 에이전트 MD에 넣지 않는다(9단 골격에 점수 섹션이 없다 — §2.2). 배점 정의는 운영 프로젝트의 스킬 정의 파일에 두고, 산정했다면 그 결과는 학습 보고서(§6.4)의 선택 항목과 malgnai-hub 기록에 남긴다.

**중요**: 키워드 점수는 보조 지표다. 키워드 점수가 높아도 실제 산출물 진단에서 약점(예: 페르소나 편중)이 발견되는 경우가 있다 — 실제 역량은 산출물로 판단한다.

## 3.2 경험 점수 적립 체계

| 이벤트 | 점수 |
|--------|------|
| 프로젝트 완료 참여 | +5점 |
| 재작업 없이 1회 통과 | +3점 |
| 리뷰어 Critical 0건 | +2점 |
| `agent_learning_record` 1건 기록 (§6.1) | +1점/건 |
| 재작업 발생 | -2점 |

**적립 절차**:
1. 프로젝트 완료 후 PM이 trainer에게 "경험 점수 갱신" 지시
2. Trainer가 malgnai-hub `agent_learning_record`로 이력과 점수를 기록(§6.2) — MD에는 이력 행을 추가하지 않는다
3. 그 경험이 낳은 **규칙**이 있으면 그것만 해당 에이전트 MD 또는 knowledge에 현재형으로 반영

## 3.3 최종 점수 공식

```
최종점수 = 스킬점수 × 0.8 + 경험점수 × 0.2
```

**등급 정의**:

| 등급 | 점수 범위 | 의미 |
|------|----------|------|
| S | 90~100점 | 벤치마크 — 다른 에이전트의 학습 표준으로 활용 |
| A | 85~89점 | 우수 |
| B | 70~84점 | 양호 — 목표 기준선 |
| C | 55~69점 | 개선 필요 — 집중 학습 스케줄 수립 |
| D | 55점 미만 | 집중 학습 대상 — 즉시 모드 1 실행 + evaluator에 산출물 진단 요청 |

**핵심 요약**: "스킬 80% + 경험 20%, 70점 미만이면 즉시 행동."

# 4장. 지식 문서(knowledge) 관리 체계

## 4.1 knowledge 폴더 구조

```
knowledge/  (이 플러그인 기준 상대 경로)
├── common/          ← 전체 공통 (token-efficient, beyond-mediocre 등)
├── leadership/      ← pm, trainer
├── planning/        ← planner, researcher
├── proposal/        ← capture-strategist, rfp-analyst
├── finance/         ← finance
├── marketing/       ← marketer
├── design/          ← ux-designer, visual-designer
├── architecture/    ← architect
├── backend/         ← backend-dev
├── frontend/        ← frontend-dev
├── quality/         ← qa-engineer
├── devops/          ← devops
├── writing/         ← writer
├── presentation/    ← presenter
├── localization/    ← localizer
└── review/          ← reviewer (재사용 페르소나 자산)
```

> **회고 교훈은 이 트리에 파일로 쌓지 않는다.** 모드 2(프로젝트 회고)의 결과는 malgnai-hub에 기록하고(`decision_record`/`work_record`, 에이전트 역량으로 남길 것은 `agent_learning_record`), 그 교훈을 문서로 반영하는 것은 모드 4다 — 반영 위치는 별도 교훈 폴더가 아니라 해당 **도메인 디렉토리**(위 트리)와 에이전트 MD다.

## 4.2 스킬별 지식 문서 작성 기준

**좋은 knowledge 파일의 4요소:**

| 요소 | 설명 | 금지 패턴 |
|------|------|-----------|
| 문제 상황 | 어떤 상황에서 이 문서를 읽어야 하는가 | "항상 중요하다" |
| 핵심 원칙 | 이 스킬의 본질적 판단 기준 | 출처 없는 권고 |
| 구체적 패턴 | 실제로 적용할 수 있는 절차·예시·체크리스트 | 개념만 나열 |
| 반례/주의 | 이 문서가 틀리는 경우 | 케바케로 끝나는 문서 |

## 4.3 교훈 일반화 게이트 (4부 구조)

단일 사례에서 얻은 교훈을 영구 규칙으로 올리기 전 4부 구조(전제조건/권장행동/반례/판별질문)를 반드시 채운다. **구조 정의와 작성 예시의 정본은 Skill `reflect-lessons` "교훈 승격 게이트"와 Skill `project-retrospective` 3단계다** — 여기서는 왜 이 게이트가 있는지만 남긴다.

전칭 규칙("무조건 X하라")은 반례가 비어 있어 적용자가 상황을 가릴 수 없다. 반례와 판별 질문이 채워져야 다음 사람이 자기 상황에 이 교훈이 해당하는지 스스로 판정할 수 있고, 그래야 규칙이 맥락 없이 오적용되지 않는다.

## 4.4 업데이트 주기 및 방법

| 트리거 | 액션 |
|--------|------|
| 프로젝트 완료 후 회고 (모드 2) | 교훈을 malgnai-hub에 기록 — knowledge/MD 반영은 모드 4가 전담 |
| 에이전트 산출물 약점 발견 | 해당 에이전트 knowledge 보강 |
| 외부 베스트 프랙티스 수집 | 해당 폴더 knowledge 추가 |
| MD 최적화 (모드 6) | 분기 1회 — 수동 트리거만 허용 |

**핵심 요약**: "4부 게이트를 통과한 교훈만 knowledge에 영구 등록한다."

# 5장. 훈련 실행 절차 — 어디가 정본인가

**이 문서에는 모드별 절차를 싣지 않는다.** 모드 번호·명칭·트리거의 정본은 `agents/trainer.md`의 "스킬 상세 — 실행 모드"이고, 각 모드의 실행 절차 정본은 그 표가 지정하는 스킬이다.

| 모드 | 절차 정본 |
|------|-----------|
| 1: 개별 에이전트 학습 (전원 학습은 이 모드를 전체 에이전트에 순회 적용한 것이며 별도 번호가 아니다) | Skill `agent-upskill` |
| 2: 프로젝트 회고 | Skill `project-retrospective` |
| 3: 주제별 학습 | Skill `topic-learning` |
| 4: 교훈 반영 | Skill `reflect-lessons` |
| 5: 페르소나 자산화 | 수동 — `agents/trainer.md` 모드 5 |
| 6: MD 최적화 | 수동 — `agents/trainer.md` 모드 6 |
| (모드 아님) 산출물 기반 진단·Scorecard 채점·승격 | `agents/evaluator.md` + Skill `domain-training-scorecard-eval` |

**여기에 절차 사본을 다시 만들지 않는다.** 같은 절차가 두 곳에 있으면 한쪽만 갱신돼 어긋나고, "정본은 저기"라는 면책 한 줄이 낡은 사본을 정당화하는 장치로 작동한다.

이 장이 남기는 판단 근거는 두 가지다.

- **산출물 기반 진단은 trainer의 모드가 아니다.** 모드 1이 "MD가 잘 쓰여 있나"를 보는 데 비해 이 진단은 "실제로 잘 해내는가"를 본다 — 채점하는 쪽과 채점 결과로 MD를 고치는 쪽이 같으면 자기 채점이 되므로 evaluator가 진단·판정하고 trainer가 반영만 이어받는다.
- **"토큰 최적화"는 독립 모드가 아니라 상시 규율이다**(§1.2 원칙 4). MD를 손대는 모드(1·3·4·6)마다 자기중단·압축반환·(리더형)서브감독 3종 박제를 함께 점검한다.

# 6장. 학습 이력 관리

## 6.1 학습 이력의 보관 위치

**이력의 정본은 malgnai-hub `agent_learning_record`다. 에이전트 MD에는 이력을 쌓지 않는다** — 9단 골격에 이력 섹션이 없고(§2.2), MD 본문은 "지금 무엇이 참인가"만 담기 때문이다. 학습의 결과로 MD에 남는 것은 이력 한 줄이 아니라 **규칙 한 줄**이며, 날짜·경위 없이 현재형으로 적는다.

**한 줄 요지 형식** (hub 기록의 title로 쓴다):
```
2026-07-09 API 버전 표기 원칙 주입 (architect) (+1점)
2026-07-09 페르소나 발산형 구성법 학습 (reviewer) (+1점)
```

## 6.2 프로젝트 경험 기록

프로젝트 완료 후 에이전트별로 `agent_learning_record`에 1건씩 남긴다. **기여와 성과는 측정 가능한 값으로 적는다** — "잘 했다"가 아니라 재작업 횟수·Critical 건수로.

```
프로젝트 | 기여 | 성과 | 경험점수
malgnuniv | API 명세 전체 설계 | 재작업 0회, Critical 0건 | +8점
```

점수 계산: 완료(+5) + 재작업없음(+3) = +8점

## 6.3 malgnai-hub agent_learning_record 활용

학습 완료 시마다 에이전트별로 1회 호출:

```
agentName: "architect"
type: "experience"        # experience | external | peer_feedback | discussion 중 하나만 허용
title: "API 설계 스킬업 — 버전 표기 원칙 박제"
content: "API 경로에 /v1/ 미포함 패턴 발견. MD 핵심 원칙에 버전 표기 의무화 추가.
          knowledge/architecture/api-design-guide.md에 버전 전략 섹션 신설."
source: "knowledge/architecture/api-design-guide.md"   # 예시 경로
idempotencyKey: "upskill-architect-2026-07-09"         # 재호출해도 중복 행이 생기지 않게 하는 키
```

## 6.4 학습 보고서 구조

매 학습 세션 종료 후 PM에게 반환하는 보고 형식:

```
학습 대상: [에이전트명]
학습 모드: 모드 [N]
이전 Scorecard 총점: [0~100 또는 "최초 회차"]
(선택) 키워드 점수: 이전 [스킬/100, 경험/100, 최종/100] → 이후 [스킬/100, 경험/100, 최종/100]

주입 내용:
- [학습 항목 1] → knowledge/[경로] 또는 MD [섹션]
- [학습 항목 2] ...

산출물 진단 결과: (evaluator 진단 결과를 반영한 경우 — 5장)
- 약점 인용: "[실제 파일에서 발견한 약한 문장]"
- 처방: [MD 또는 knowledge 어디에 무엇을 박제했나]

malgnai-hub 기록: 완료 / 미완료
```

**점수 칸 채우는 법**: `이전 Scorecard 총점`은 malgnai-hub `agent_get_context`(`agentName`, `scoreHistoryLimit`)로 조회한 응답의 `latestScore.overallScore`를 그대로 적는다 — 응답 최상위(`agentName`/`latestScore`/`scoreHistory`/`recentLearnings`)에는 `overallScore`가 없으므로 `latestScore` 안을 열어야 값에 닿는다. `latestScore`가 `null`이면(점수 이력 없음) "최초 회차"로 적는다 — 조회로 확인되지 않는 값을 추정해 채우지 않는다. 이번 학습의 효과는 다음 채점 회차에서 evaluator가 낸 Scorecard 총점으로 확인하며, trainer가 학습 직후에 스스로 매기지 않는다. 키워드 점수(§3.1)는 보조 지표이므로 산정한 회차에만 선택 항목으로 적는다.

**핵심 요약**: "이력은 전부 malgnai-hub에, MD에는 그 학습이 낳은 규칙만 현재형으로."

# 7장. 에이전트 MD 갱신 절차

## 7.1 백업 방법

**모든 MD 갱신 전 필수 선행 단계:**

- **이 플러그인 번들(`agents/`)을 직접 갱신하는 경우(기본 케이스)**: git으로 버전 관리되므로 별도 cp 백업이 필요 없다. 갱신 전 `git status`/`git diff`로 현재 상태를 확인하고, 필요하면 `git stash` 또는 별도 브랜치로 분리한다. 되돌릴 커밋 해시를 기록해 둔다.
- **에이전트 MD를 전역 `~/.claude/agents`에서 개별 운용하는 경우(이 플러그인과 별개의 로컬 구성일 때만)**:
  ```bash
  cp -r ~/.claude/agents ~/.claude/agents_backup_$(date +%Y%m%d)
  ```
  백업 경로: `~/.claude/agents_backup_YYYYMMDD/`
  백업 확인: `ls ~/.claude/ | grep agents_backup`

## 7.2 MD 재작성 체크리스트

```
[ ] 1. 백업 완료 확인
[ ] 2. 기존 MD 읽기 → 교훈 목록 추출 (Before 목록 작성)
[ ] 3. 9단 골격(frontmatter→핵심원칙→역할경계→스킬상세→전제조건→자기검증→산출물→학습자료→토큰효율)으로
       재작성 — 상세는 §2.2, 실물 예시는 §2.3
[ ] 4. 교훈 목록 대조 — Before 개수 = After 개수 확인
[ ] 5. 금지·승인 항목이 `## 역할 경계`에 들어갔는지 확인. 스킬 정의 파일(skill-definitions.js
       EMPLOYEE_CARDS)이 있는 운영 환경이면 동기화(미번들 — 없으면 각 에이전트 MD를 직접 대조)
[ ] 6. 학습 자료 섹션 — 필수/참고 2단 구성, 인용한 경로가 실재하는지 ls로 대조
[ ] 7. 토큰 효율 섹션 — 리더형은 서브 감독 포함 여부 확인
[ ] 8. 이력·점수 잔재 0 확인 (점수 태그·last_trained·경험 이력 표가 남아 있지 않은가) →
       남길 값은 malgnai-hub `agent_learning_record`로 기록
```

## 7.3 기존 노하우 보존 검증 방법

**원칙: 교훈 내용 손실 0**

마이그레이션 전후로 "교훈 목록"을 만들어 대조한다:

```
Before: [교훈A, 교훈B, 교훈C, ...]
After:  [교훈A, 교훈B, 교훈C, ...]  ← 동일 개수, 동일 핵심 내용
```

누락이 있으면 After에 추가 후 재검증. 개수가 일치할 때만 완료 처리.

**주의**: 표현 압축은 허용, 의미 손실은 불허. 모드 6(MD 최적화)도 동일 원칙 적용.

**핵심 요약**: "백업 먼저, 교훈 목록 대조로 손실 0 검증 후 완료."
