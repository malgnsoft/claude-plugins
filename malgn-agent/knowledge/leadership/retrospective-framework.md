# 프로젝트 회고 프레임워크

> 출처: Glitter AI Lessons Learned Guide, Plaud Lessons Learned Templates, Agilemania Retrospective Guide

## 회고의 목적

프로젝트 완료 후 성공/실패 패턴을 추출하여 knowledge에 반영함으로써
다음 프로젝트에서 같은 실수를 반복하지 않고, 효과적 패턴을 재활용합니다.

## 회고 실행 절차

### 0단계: 산출물 실사 (회고 전 선행, 생략 불가)

교훈 수집에 앞서, 각 에이전트가 "했다"고 보고한 작업의 산출물이 실제로 존재하는지 `ls`로 확인한다. UI/UX 작업이면 `docs/screenshots/`에 이미지가, 패널 리뷰면 `docs/reviewer/personas/persona-*.md`가 실재하는지 본다. **산출물이 보고와 불일치하면(예: "화면 검토"인데 캡처 0개) "잘 됐다"고 칭찬하지 말고 결함으로 기록**한다. 회고가 유령 작업을 칭찬하면 다음에 같은 실수가 학습된다.

- **존재 검증을 넘어 적합성(fitness) 검증까지 (생략 불가):** 파일이 **있다**고 끝이 아니다. 그 산출물이 **검증 대상을 실제로 행사하는가**까지 본다. (정적 `goto` 캡처가 *존재*하고 Read까지 됐어도, **인터랙션(탭 클릭·드로어·active)을 전혀 안 거치면** "탭 줄넘침을 지적하면서 탭 누른 화면이 없는" 반쪽 리뷰가 될 수 있다.) 즉 ① "패널로 리뷰" → 페르소나 파일 N개 **존재** + 각 페르소나가 서로 다른 관점을 **실제로 봤는지**, ② "UI/UX 검토" → 캡처 **존재** + **인터랙션 상태(클릭 이동·active·토글)까지** 캡처됐는지. 둘 다 충족돼야 통과. 한쪽만이면 "정적만 확인됨, 인터랙션 미검증"으로 결함 기록.
- **반복 실패는 가중 처리:** 같은 종류의 "안 한 걸 한 것처럼 보고"(유령 보고)가 **두 번째** 나타나면, 개별 결함이 아니라 **구조적 문제**로 다룬다. 1차 교육의 게이트가 왜 안 막았는지(보통 "존재만 검증, 적합성 미검증" 또는 "조건부·물렁한 문구")를 회고에 명시하고 trainer 연계로 게이트를 **그 빈틈 위주로** 격상시킨다 (과한 프로세스 추가가 아니라 기존 게이트의 구멍 메우기). (수령 검증 원칙: `common/verifiable-output-and-honesty.md`)

### 1단계: 데이터 수집
- STATUS.md(진행 상태 단일 소스)에서 전체 타임라인과 이벤트 확인, 장기 이력은 malgnai-hub 조회로 보완
- 각 에이전트 산출물의 품질 기록 확인 (재작업 횟수, 피드백 내용)
- 사용자 피드백 내용 정리

### 2단계: 분석 (Start/Stop/Continue + SWOT)

#### Start (새로 시작할 것)
- 이번에 안 했지만 했으면 좋았을 것
- 예: "보안 점검을 개발 완료 후가 아니라 설계 단계에서 시작"

#### Stop (중단할 것)
- 효과 없이 시간만 소모한 것
- 예: "불필요하게 상세한 중간 보고"

#### Continue (유지할 것)
- 효과적이었던 패턴
- 예: "PRD 작성 후 아키텍트와 바로 연결"

#### SWOT 보완
- **Strengths**: 팀 구성에서 잘 한 점
- **Weaknesses**: 조율에서 부족했던 점
- **Opportunities**: 새로 발견한 효율화 기회
- **Threats**: 반복될 수 있는 리스크

### 3단계: 교훈 문서화

개인 로컬 경로(`~/.claude/knowledge/lessons/...` 등)가 아니라 malgnai-hub 기록 도구로 남긴다 — 결정·판단형 교훈은 `decision_record`(reason/impact에 실질을 적는다), 작업·절차형 교훈은 `work_record`(result/nextAction), 특정 에이전트의 역량으로 남길 것은 `agent_learning_record`. 아래 구조를 그 호출의 본문 템플릿으로 사용:

```markdown
# [프로젝트명] 회고

완료일: YYYY-MM-DD
참여 에이전트: [목록]
프로젝트 유형: [제안서/개발/분석/디자인]

## 잘 된 점 (Continue)
- [패턴/기법] — 효과: [구체적 효과]

## 개선할 점 (Stop/Start)
- [문제] — 개선안: [구체적 대안]

## 에이전트별 성과
| 에이전트 | 산출물 품질 | 재작업 횟수 | 특이사항 |
|---------|-----------|-----------|---------|
| researcher | 양호 | 0 | 출처 명시가 좋았음 |
| planner | 보통 | 1 | 비기능 요구사항 누락 |

## 새로 배운 것
- [에이전트명]: [교훈] → 반영할 파일: [knowledge 경로]

## knowledge 업데이트 내역
- [파일 경로]: [추가/수정 내용 요약]
```

### 4단계: knowledge 반영 (자율 경계 안에서는 사용자 승인 없이 진행)

> **PM은 `agents/`·`skills/`·`knowledge/`를 직접 편집하지 않는다.** 전역 자산 승격 실행은 PM 권한 밖이다 — 초안 작성·보강은 **trainer**, 채점·판정과 승격 실행은 **evaluator** 소관이다(pm.md "PM 권한 참조표"의 "전역 자산(agents/skills/knowledge) 승격 실행" 행). PM이 하는 일은 대상 선정·의도 전달·실물 대조 검증·기록이다.

- 새로운 패턴 → 해당 영역 knowledge 파일에 추가하도록 **trainer에 위임**
- 기존 가이드 수정 필요 → 해당 파일 갱신을 **trainer에 위임**
- 에이전트 MD 보강 필요 → 해당 에이전트 MD의 스킬 상세에 추가하도록 **trainer에 위임**
- **trainer 연계:** 이번 교훈이 특정 에이전트 역량에 직접 닿으면 trainer를 호출해 그 에이전트의 MD/knowledge에 반영시킨다.
  - 일반 교훈/실수 패턴 → **trainer 모드 4**(`/reflect-lessons`, pending 교훈 → 에이전트별 분류 → Knowledge/MD 반영)
  - **특정 에이전트의 산출물이 질적으로 약했으면**(평범함·천편일률·근거 부족 등) → **evaluator**(산출물 진단·Scorecard 채점의 실행 주체). "에이전트별 성과 추적" 표와 약한 산출물의 실제 경로를 evaluator에게 넘긴다. evaluator가 판정하면 trainer가 개선안을 MD/knowledge에 반영한다.
- **반영 전 trainer의 "교훈 일반화 게이트" 통과**: 4부 구조(전제조건→권장 행동→반례→판별 질문), 전칭/과잉상대화 금지.
- **자율 경계 판단** (PM 대원칙 기준 — 사용자 승인이 필요한지의 기준이지, PM이 직접 편집해도 되는지의 기준이 아니다): 단일 에이전트 국소 보강·malgnai-hub 교훈 기록·게이트 통과한 교훈은 **사용자 승인 없이 위임해 반영**. 전칭 규칙 신설·여러 에이전트 공통 자산 변경·기존 원칙 충돌·구조 변경은 **사용자 승인 후** 반영. 애매하면 멈추고 올린다. 어느 쪽이든 파일을 고치는 주체는 trainer이고 승격은 evaluator다.

### 5단계: 검증
- 업데이트한 knowledge 파일이 정상적으로 읽히는지 확인
- README.md에 새 파일이 등록되어 있는지 확인

## 회고 실행 시점 (자동 가동 — 사용자가 시키지 않아도 돈다)

자기개선 루프의 방아쇠는 **작업 완료**다. 사람의 지적을 기다리지 않고 PM이 스스로 회고를 가동한다.

| 시점 | 트리거 | 자동? |
|------|--------|------|
| **프로젝트/주요 작업 완료** | 최종 보고서 제출 직후 → PM이 자동 회고 | ✅ 자동 |
| **사용자 교정 발생** | 사용자가 중간에 산출물·판단을 교정/반려한 지점 → 그 자체를 교훈 후보로 자동 포착 | ✅ 자동 |
| 사용자 요청 | "회고해줘", "배운 점 정리해줘" | 수동 |
| 프로젝트 중단 | 사용자가 프로젝트 중단 선언 시 | 수동 |

**사용자 교정 포착이 핵심이다.** 사용자가 "그건 아니다", "이렇게 해라", "왜 또 그러냐"고 교정한 모든 지점은 *이미 드러난 실수*다 — 회고는 이걸 1순위 교훈 후보로 삼아, 같은 실수가 반복되지 않도록 게이트를 통과시켜 영구 자산에 반영한다. (사용자가 매번 지적할 수 없으므로, 한 번 지적된 것은 반드시 시스템에 흡수한다.)

```
    │

    │
    └──→ malgnai-hub에 교훈 기록(decision_record / work_record / agent_learning_record)
```
