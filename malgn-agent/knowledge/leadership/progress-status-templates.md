# 진행 상황 기록 템플릿 (STATUS.md)

> PM이 프로젝트 진행 상황을 추적할 때 쓰는 표준 템플릿.

> **2026-08-07 정정**: 과거 이 문서는 `progress.md`(단계별 진행 기록)와 `STATUS.md`(현재 상태 요약)를 병행하는 2-파일 모델을 정식 템플릿으로 제시했다. 이는 폐기됐다 — 진행 상태의 단일 소스는 루트 `STATUS.md` 하나뿐이며, 정확한 파일 포맷·부트스트랩 절차의 정본은 `knowledge/common/project-folder-structure.md`와 `skills/project-standards`다(§10.1 중복 서술 금지 원칙에 따라 이 문서에서 포맷을 다시 정의하지 않는다). `progress.md`라는 파일명과 "실시간 전체 로그 누적" 방식은 이 표준과 모순되므로 쓰지 않는다.

PM은 프로젝트 루트의 `STATUS.md` 하나로 진행 상황을 기록한다 — 세션을 새로 시작할 때 코드·문서를 다시 통독하지 않고 이 파일만으로 현재 상황을 파악할 수 있어야 한다.

## STATUS.md (현재 상태 요약 — 단일 소스)

위치: 프로젝트 루트의 `STATUS.md`. 기본 포맷은 `knowledge/common/project-folder-structure.md`를 참조.

```markdown
# [프로젝트명] 현황

## 진행중
- [작업/단계] — 상태, 예상 완료 시점

## 완료
- [작업] — 완료일, 결과물 위치 (decision #123)
```

과거 `progress.md`가 담당하던 "팀 구성", "다음 작업" 같은 필드가 필요하면 위 템플릿의 "진행중" 섹션 항목에 담아 축약한다(예: `- planner: 기획서 작성 진행중 — 다음: writer 착수 예정`). 별도 파일을 만들지 않는다.

리스크가 식별되면 STATUS.md의 "진행중" 섹션 항목에 리스크를 함께 명시하거나(1줄 요약), 상세는 `issue_add`로 기록하고 STATUS.md에는 id만 남긴다. (리스크 대응 전략·에스컬레이션 절차는 `risk-escalation-guide.md` 참조)

회고 완료 시 STATUS.md를 갱신해 완료를 기록한다. (회고 절차는 `retrospective-framework.md` 참조)

### STATUS.md 길이·아카이빙 규칙 (필수 — 비대화 방지)

> **배경(실제 사고):** malgnai에서 STATUS.md가 178줄·70KB(약 34,000토큰)까지 비대해진 적이 있다. 원인은 ① 완료 항목을 검증 케이스·파일 목록·되돌리기 절차까지 **통짜 문단**으로 계속 누적하고 ② 상세를 MCP로 이관하지 않았으며 ③ 완료 섹션에 **길이/개수 상한·아카이빙 규칙이 없었기** 때문이다. STATUS.md는 **SessionStart 훅으로 매 세션 자동 주입되는 push 문서**라, 비대해지면 세션마다 토큰을 크게 낭비한다 → 짧게 유지하는 것이 토큰 비용에 직결된다.

- **완료 항목은 "1줄 요약 + MCP id 참조"가 원칙.** 검증 케이스·파일 목록·되돌리기 절차·결정 근거 같은 **상세는 STATUS.md에 쓰지 않는다.** 상세는 `decision_add`(주요 결정)·`memory_add`(교훈·요약)·`issue_add`(장애물)로 MCP에 남기고, STATUS.md에는 그 요약 한 줄과 id만 적는다. (예: `- 로그인 리팩터 완료 — 세션 검증 강화 (decision #142)`)
- **완료(✅) 섹션은 최근 5~7개만 유지한다.** 초과분은 **삭제**한다 — 원본이 MCP에 있으므로 손실이 아니다. 과거 이력은 `decision_list` / `memory_search` / `issue_list`로 조회한다.
- **그 자리에서 이관·압축(PM 책임).** 상태 갱신 시 완료 섹션이 7개를 넘거나 개별 항목이 **문단화되기 시작하면**, 미루지 말고 그 자리에서 MCP로 이관하고 STATUS.md는 1줄로 압축한다.
- **진행 중(🚧) 섹션은 "완료 전까지 무제한 누적" 예외가 아니다.** 하나의 이니셔티브가 여러 세션에 걸쳐 진행되며 단계마다 결정을 이미 `decision_add`로 MCP에 남겼다면, STATUS.md 쪽 서술은 매번 append하지 말고 그 자리에서 "현재 어디까지 왔고 다음 게이트가 뭔지" 1~2줄 + 최신 decision id로 즉시 재압축한다. 지나간 하위단계(예: v1→v2 같은 이전 리비전, 이미 해소된 우려사항)는 완료 항목과 동일하게 취급해 접어 넣는다 — "아직 완료가 아니다"는 문단을 계속 쌓아도 되는 이유가 아니다.
- **헤더 라인(`_최종 갱신: ...`)은 완료/진행중 섹션과 별개로 매번 완전 교체(overwrite)한다 — "직전:"/"이전:" 체이닝 금지.** 헤더는 그 시점의 최신 상태 **1~2문장, 약 150자(공백 포함) 이내**만 담는 요약이지 변경 로그가 아니다. 과거 세션 이력이 필요하면 헤더가 아니라 "최근 완료" 섹션(1줄+MCP id) 또는 `decision_add`/`memory_add`로 보낸다. 헤더 갱신 직전 자기점검: "지금 쓰는 문장이 이전 헤더의 단어·문장을 포함/참조하는가?" → 그렇다면 걷어내고 새 문장만 남긴다. (배경 사고 사례: `lessons/malgnai-status-header-chaining.md` — 헤더 한 줄에 10개 이상 과거 세션이 "직전:"으로 사슬처럼 이어져 수 KB 문단이 된 실사고)
