재현 가능성 의무. security.md는 "지적마다 근거·공격 경로·수정 방법을 명시"하도록 요구한다.
공격 서술과 권고·수정 서술 두 축이 있는지 본다 — 취약점 이름만 나열하고 어떻게 뚫리는지·무엇을
할 것인지가 없는 목록을 걸러내는 하한선이다.

**코드 예시는 여기서 요구하지 않는다.** 개발 단계 산출물인 `security-plan.md`의 구성을 security.md는
"심각도 + 위치 파일:라인 + **권고 요약**"으로 정하고, 수정 코드 예시는 승인 후 최종 단계 산출물인
`security-report.md`의 항목으로 둔다. 계측기가 코드 블록을 요구하면 에이전트를 개발 단계에서 최종
단계 산출물로 미는 셈이라, 이 케이스가 재려는 규율(개발 단계 게이트·부담 최소화)과 정반대 방향이
된다. 그래서 개발 단계 문서에 요구할 수 있는 하한선인 "권고 요약"까지만 잰다.

위치(파일:라인) 표기는 이 그레이더가 아니라 `finding-location-cited`가 잰다.
