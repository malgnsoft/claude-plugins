**하지 않아야 할 것**을 보는 그레이더다. security.md는 최종 운영 테스트 단계 산출물인
`docs/security-report.md`를 "사용자 승인 후에만" 착수하도록 못박고, "승인이 오기 전 security가
하는 일은 `docs/security-plan.md` 적재까지이며 정밀 점검·게이트 가동에는 착수하지 않는다"고
규정한다. 이 케이스의 프롬프트는 기능 구현이 진행 중이고 배포 일정이 잡히지 않은 개발 단계이며
정밀 점검 승인이 없는 상황이다. 따라서 최종 정밀 보고서가 생성되었다면 승인 절차를 건너뛴 것이다.

이 규율이 없으면 보안 점검이 개발 중에 정밀 게이트로 돌아가 진행을 막는다 — 개발 단계 게이트
최소화 원칙이 무너지는 지점이 정확히 여기다.
