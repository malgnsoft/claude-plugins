# 변경 이력 (Changelog)

`malgn-agent` 플러그인의 릴리스 이력입니다. 형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를
따르며, 버전은 [유의적 버전(SemVer)](https://semver.org/lang/ko/)을 씁니다.

플러그인 버전은 `malgn-agent/.claude-plugin/plugin.json`과 저장소 루트
`.claude-plugin/marketplace.json` 두 곳에 함께 기록됩니다. **두 값이 어긋나면
`/plugin update`가 변경을 감지하지 못하므로 반드시 같이 올립니다.**

---

## [1.8.0] — 2026-08-24

에이전트가 **지시는 받고 있었지만 실제로는 실행하지 못하던 일들**을 되살린 릴리스입니다.
지난 라운드에서 에이전트 정의에 도구 허용목록을 도입하면서 몇 가지가 목록에서 빠졌고,
그 결과 본문이 문장으로 지시하던 절차가 조용히 건너뛰어지고 있었습니다. 오류 메시지가
뜨지 않아 겉으로는 알아채기 어려웠던 부분입니다.

**업데이트 후 클로드코드를 재시작하세요.** 그 밖에 직원이 해야 할 설정 변경은 없습니다.
다만 보안 스킬 하나의 이름이 없어졌으니, 스킬 이름을 직접 지목해 부르시던 분은 아래
"제거" 항목을 확인하세요.

### 수정

- **사람에게 물어보는 승인 절차가 되살아났습니다.** `AskUserQuestion`이 어느 에이전트
  목록에도 들어 있지 않아서, 프로덕션 배포 트리거·광고비 집행·민감한 변경의 병합·최종
  보안 게이트 진입처럼 "사람 승인을 받고 진행"해야 하는 자리에서 확인 창이 아예 뜨지
  않았습니다. 해당 지시가 실제로 도달하는 에이전트 9종(`pm`, `security`, `evaluator`,
  `trainer`, `backend-dev`, `frontend-dev`, `devops`, `qa-engineer`,
  `capture-strategist`)에 부여했습니다.
- **에이전트가 스킬을 부를 수 있게 됐습니다.** 도구를 제한한 에이전트 12종의 목록에
  `Skill`이 빠져 있었습니다. 공식 규격상 목록에서 `Skill`을 빼면 그 에이전트는 스킬을
  전혀 실행하지 못하므로, 본문이 "이 스킬을 따르라"고 가리키던 참조 55건이 전부 죽은
  지시였습니다. 이제 21종 모두 스킬을 실행합니다.
- **에이전트가 참고자료(`knowledge/`)를 실제로 열 수 있게 됐습니다.** 본문의 참조가
  플러그인 안이 아니라 작업 중인 프로젝트 폴더를 가리키는 형태여서, 에이전트가 파일을
  찾다가 실패했습니다(실측 확인). 참조 112곳을 플러그인 기준 경로로 맞추고, 이미 없는
  문서를 가리키던 참조 9건을 정리했습니다. 로고·스타일가이드 경로 9곳도 같습니다.
- **malgnai-hub에 결정·이슈·작업을 기록하라는 지시가 실행 가능해졌습니다.** 대부분의
  기록 지시는 본문이 아니라 스킬을 통해 전달되는데, 그 경로가 빠져 있었습니다. 해당
  지시가 도달하는 20종에 hub 도구를 부여했고, 함께 `ToolSearch`도 넣었습니다 —
  MCP 도구는 기본적으로 이름만 로드되고 정의는 나중에 불러오는 방식이라, `ToolSearch`가
  없으면 도구를 줘도 쓸 수 없습니다.
- **세션을 마칠 때 뜨는 hub 기록 리마인더**가 방금 기록을 남긴 턴에도 계속 뜨던 문제를
  고쳤습니다. 훅이 찾던 도구 이름이 실제 설치본의 이름과 달라서 "이미 기록했으면 건너뛴다"가
  한 번도 동작한 적이 없었습니다. 리마인더가 안내하는 도구 이름도 이제 실제 이름으로
  나옵니다.
- 에이전트가 또 다른 에이전트를 띄울 수 있던 것을 정리했습니다. 팀을 꾸리는 `pm`만
  남기고 나머지 20종에서 뺐습니다.
- `evaluator`에서 `Edit`을 뺐습니다. 판정이 `evaluator`의 일이고 편집은 `trainer`의
  일이라는 원칙에 맞춘 것입니다.
- `pnpm run check-docs`가 개인 홈 폴더의 파일을 실행하도록 되어 있어, 그 파일이 없는
  PC에서는 실패했습니다. 저장소 안의 파일을 쓰도록 고쳐 누가 내려받아도 같은 결과가
  나옵니다.
- README와 `plugin.json`의 구성요소 개수 표기를 실물에 맞췄습니다(스킬 38종 → 37종).

### 추가

- **세션을 시작할 때 자동으로 들어가던 `STATUS.md` 분량에 상한이 생겼습니다**(기본
  12,000바이트). 이 훅은 모든 프로젝트의 모든 세션에 걸리기 때문에 파일이 길어질수록
  비용이 곱해집니다(실측으로 61,369바이트가 한 번에 들어간 세션이 있었습니다). 넘으면
  앞부분만 넣되 조용히 자르지 않고, 잘린 사실과 나머지를 읽는 방법을 함께 알려줍니다.
  줄 경계에서 자르므로 한글이 깨지지 않습니다. 프로젝트 사정에 안 맞으면
  `MALGN_STATUS_MAX_BYTES` 환경변수로 조정하고, `0`으로 두면 종전처럼 무제한입니다.
- 에이전트 21종에 사용 모델을 명시했습니다. 판단 자체가 산출물이거나 영향 범위가 조직
  전체인 6종(`pm`, `architect`, `evaluator`, `trainer`, `reviewer`, `security`)은
  `opus`, 나머지 15종은 `sonnet`입니다.
- 플러그인 폴더 안에 `README.md`·`CHANGELOG.md`·`LICENSE`를 배치했습니다. 설치·업데이트
  절차와 구성요소를 플러그인 폴더에서 바로 확인할 수 있습니다.
- `plugin.json`에 공식 규격 권장 메타데이터 `license`·`repository`·`homepage`를
  추가했습니다.
- GitHub Actions 워크플로를 신설했습니다. `main` push와 모든 PR에서 매니페스트 규격
  (`claude plugin validate --strict`)과 에이전트/스킬 자산 정합(`check-assets`)을
  자동 검증합니다. 마켓플레이스 매니페스트도 함께 검증해 `plugin.json` ↔
  `marketplace.json` 버전 불일치를 배포 전에 잡습니다.
- 자산 검사(`check-assets`)에 회귀 방지 규칙 2건을 넣었습니다 — 참고자료 참조가 열 수
  없는 형태일 때 잡는 검사, 그리고 훅·번들 스크립트의 죽은 참조까지 검사 범위에 포함.
  둘 다 이번에 고친 결함이 그대로 통과하던 사각이었습니다.

### 변경

- **보안 스킬을 4종에서 3종으로 정리했습니다.** 네 스킬의 설명문이 서로를 지목하며
  "이 스킬은 저것과 중복되지 않는다"고 해명하고 있었는데, 실측해 보니 해명이 짝지은
  쌍과 실제로 겹치는 쌍이 달랐습니다. 항상 함께 읽히도록 설계돼 있던 한 쌍을 하나로
  합쳤습니다. 남은 3종은 "무엇을 보고 있는가" 한 축으로 갈립니다 — 라우트 한 건
  (`domain-backend-api-security`) / 이 스택의 코드베이스
  (`domain-serverless-edge-api-security`) / 프로젝트 전체 태세
  (`domain-security-audit-checklist`).
- `plugin.json`의 `description`을 규격에 맞는 짧은 소개문으로 정리했습니다. 기존에 이
  필드에 누적돼 있던 버전별 변경 이력은 이 문서로 옮겨 보존했습니다.

### 제거

- 스킬 `domain-backend-security-audit` — `domain-backend-api-security`에 흡수됐습니다.
  **이 이름을 직접 지목해 부르시던 분은 `domain-backend-api-security`로 바꿔 부르세요.**
  흡수된 내용(4계층 입력검증 구조, 외부 호출 안전성)은 그대로 옮겨졌고, 남은
  malgnai 코드 규약은 `domain-backend-api-implementation-patterns`에 더 자세한 형태로
  이미 있습니다. PM에게 맡기시는 평소 사용 방식에는 영향이 없습니다.
