# 변경 이력 (Changelog)

`malgn-agent` 플러그인의 릴리스 이력입니다. 형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를
따르며, 버전은 [유의적 버전(SemVer)](https://semver.org/lang/ko/)을 씁니다.

플러그인 버전은 `malgn-agent/.claude-plugin/plugin.json`과 저장소 루트
`.claude-plugin/marketplace.json` 두 곳에 함께 기록됩니다. **두 값이 어긋나면
`/plugin update`가 변경을 감지하지 못하므로 반드시 같이 올립니다.**

## [미출시]

아직 배포되지 않은 항목입니다. 다음 릴리스 항목에 합류합니다.

### 변경

- 문서-코드 드리프트 체커(`doc-drift.mjs`) 상단 주석의 매니페스트 형식 예시 한 줄을 범용 예시로
  교체했습니다. 예전 예시는 이 플러그인을 만드는 저장소의 실제 검사 값이라 설치 환경에 그대로
  대입할 수 없었습니다. 이제 `docFile`+`docRegex`(문서 원문에서 기대값을 직접 캡처하는 방식)
  사용법을 API 라우트 개수라는 일반적인 상황으로 보여줍니다. 검사 동작과 종료 코드는 바뀌지
  않았습니다.

## [1.8.14] — 2026-08-26

결함 수정 릴리스입니다.

### 수정

- `trainer`의 자기검증 체크리스트에 "기록주체 서술을 고칠 때는 문구가 아니라 도구명(`decision_record`
  등, 리네이밍되지 않는 식별자)으로 전수 grep해 사이트 목록을 먼저 만든다"는 절차를 신설했습니다.
  같은 뿌리 결함이 문구 기반 검색으로 반복 재발하던 것을 막습니다.

  `sessionstart-context.mjs`(세션 경고)까지 포함하도록 정정하고, 실재하지 않던 앵커를 실제 진입점
  마커로 고쳤습니다. 재발을 막는 사양-구현 대조 검사(`scripts/check-doc-drift-spec.mjs`)를 신설해
  `check-assets`에 편입했습니다.
- `topic-learning` 스킬의 완료 보고 절차에서 trainer 자신의 학습 이력 기록(`agent_learning_record`)
  언급이 빠져 자매 스킬 `agent-upskill`과 비대칭이던 것을 맞췄습니다.
- `evaluator`의 스킬 접두어 게이트 판정 기준을 "이름이 몇 번 grep되는가"에서 "상시 비용인가 조건부
  비용인가"(knowledge 경유 간접 도달 포함)로 재정의했습니다. 기존 기준은 공통 knowledge를 경유해
  전 에이전트에 상시로 깔리는 스킬을 좁은 이름으로 오판정해 불필요한 개명을 유발했습니다.
- `evaluator`의 자기검증 체크리스트에 `agent_score_record` 쓰기·읽기 왕복(판정 전 `agent_get_context`로
  이전 점수 조회, 판정 후 기록)이 완료 정의임을 명시했습니다. 기존엔 쓰기만 게이트돼 있어 다음
  판정 회차가 이전 점수를 조회하지 못하는 결함이 있었습니다.
- `agent-training-guide.md` §6.4가 "키워드 점수는 보조 지표"라는 §3.1 선언과 모순되게 학습 보고서마다
  키워드 점수 3칸을 필수로 요구하던 것을, Scorecard 총점(조회 가능한 값) 필수 + 키워드 점수 선택
  항목으로 정정했습니다.

### 수정

- `frontend-vue-zero-patterns` 스킬과 정본 아키텍처 문서(`vue-zero-architecture.md`)가 규정한

  `const`/`let`/`class` 값만 필요시 수동 등록)으로 정정했습니다. `agents/frontend-dev.md`에 남아
  있던 옛 절차 지시(존재가 금지된 `composables/index.js` 참조)도 함께 정정했습니다.

  Knowledge→Skill 링크 판정)을 보강했습니다.
- 토큰 사용량 수집 스크립트(`report-usage.mjs`)가 `import`만으로 수집·전송이 실행되던 결함에
  ESM 메인모듈 가드를 추가했습니다(symlink 우회까지 realpath 정규화로 방어).
- `doc-drift.mjs`가 매니페스트 값을 문서 캡처 결과와 대조하지 않고 자기 자신을 복제해 비교하던
  구조를 문서 원문에서 직접 캡처하는 방식으로 전환하고, 문서 캡처 실패를 skip이 아닌 드리프트로
  승격했습니다.

## [1.8.8] — 2026-08-25

PM 행동규율을 각 프로젝트에 전달하는 방식을 바꾸고, "초기화 해줘"가 점검하는 범위를
넓히는 릴리스입니다. **업데이트 후 클로드코드를 재시작하세요.**

### 변경

- **프로젝트의 `CLAUDE.md`가 플러그인 안에 있는 PM 행동규율 문서를 "불러오는" 방식으로
  배선돼 있었는데, 실제로는 거의 로드되지 않고 있었습니다.** 클로드코드가 저장소 밖
  파일을 불러올 때 승인 창을 띄우기 때문입니다(이 방식으로 배선된 프로젝트들을 실제로
  세어 보니 규율이 실린 것이 하나도 없었습니다). 이제는 규율 문장을 `CLAUDE.md` 본문에
  시작·종료 표시로 감싼 구역으로 직접 심습니다. 새로 만드는 프로젝트는 생성 시점에
  자동으로 심기고, **이미 쓰고 있는 프로젝트는 "PM 행동규율 다시 확인해줘"라고 요청하면**
  현재 상태를 점검해 옛 배선이면 새 방식으로 바꿔줍니다. 이때 규율의 의무가 늘어나는
  경우에는 무엇이 달라지는지 보여주고 동의를 받은 뒤에만 바꿉니다. 규율을 원하지 않으면
  거절 상태로 되돌릴 수 있고, 그 과정에서 지워진 내용은 되돌릴 수 있도록 그대로
  보여줍니다.

### 수정

- **"이 프로젝트 초기화해줘"라고 하면 진행 상태 문서(`STATUS.md`)가 있는지만 확인하고

- 프로젝트 운영 표준 스킬의 "완료 항목마다 id를 적으라"는 안내를 뺐습니다.
  malgnai-hub에서 이력을 조회할 수 있어 STATUS.md에 따로 적을 필요가 없고, 적으면 그
  자체가 매 세션 들어가는 분량이 됩니다.

### 정리

- 에이전트·스킬·참고자료 본문 곳곳에 남아 있던 "언제·누가·왜 이렇게 바꿨는지"류
  서술(합의 날짜, 이전 버전과의 비교, 내부 논의 경위)을 걷어냈습니다. 이런 서술은
  설치한 회사 입장에서 확인할 방법이 없는 내용이라 도움이 되지 않고, 매 호출마다
  분량만 차지하고 있었습니다. 규칙이 왜 필요한지에 대한 설명은 남겼습니다.

### 검사기

- 스킬이 실행하라고 지시하는 번들 스크립트, 복사해 쓰라고 안내하는 템플릿 파일이 실제로
  있는지 확인하는 검사를 추가했습니다. 지금까지는 이런 참조가 옮겨지거나 지워져도
  설치 직원이 실제로 열어보기 전까지는 아무도 몰랐습니다.
