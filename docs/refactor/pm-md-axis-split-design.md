# `agents/pm.md` 불변축/가변축 분리 — 구조 결정

- 대상: `malgn-agent/agents/pm.md`
- 작성: trainer 설계안(PM 위임) → PM이 사용자 승인 받아 보존
- 목적: 슬리밍 라운드마다 "이번엔 어디를 옮길까"를 처음부터 재판단하던 반복(3회 지적)을 끝내는 **판정 규칙**. 이 문서 자체가 다음 라운드의 입력이다 — 재판단하지 말고 아래 규칙을 적용한다.

## 1. 결론 3줄

1. 불변/가변 2분법은 pm.md 실물에 안 맞는다 — **4축**이 필요하다.
2. "가변축의 단일 목적지"는 만들지 않는다 — 이관 후보 대부분이 이미 소유 문서를 갖고 있어(실측 확인), 새 그릇을 만들면 새 중복이 생긴다. 대신 **단일 배분 규칙**(아래 §3)을 쓴다.
3. 이 설계로도 pm.md는 15 KB 예산에 도달할 수 없다(이론 하한 ≈ 24 KB). 예산 기준 자체를 pm.md에 한해 재설정하는 것이 맞는 결론이다 — `scripts/validate-agent-assets.mjs`의 `BUDGET_PM_KB`(25 KB)로 반영 완료.

## 2. 4축 판정 규칙

두 가지 관측 가능한 질문으로 축을 가른다(주관적 "훼손 금지" 판단에 맡기지 않는다).

- **Q1(트리거)**: 이 블록이 발동하는 시점을 `~할 때` 한 문장으로 쓸 수 있는가? 못 쓰면(=항상 발동) 이관 이득이 0이다.
- **Q2(가역성)**: 이 문장을 못 본 채 진행하면 되돌릴 수 없는 일(승인 없는 배포·삭제·전송·권한경계 붕괴)이 일어나는가?

| 축 | 정의 | 처분 |
|---|---|---|
| **G — 게이트축** | Q2=비가역 (트리거 유무 무관) | pm.md 잔류, **훼손·이관 금지**(강도·경계를 바꾸는 편집도 금지) |
| **S — 상시판정축** | Q1=불가(트리거 못 씀) + 가역 | pm.md 잔류, 압축은 허용(중복 값·예시 서술을 정본 지목으로 축약), **이관은 금지** |
| **C — 상황축** | Q1=가능 + 가역 + 순이득 ≥ 250 B | **이관 대상** |
| **X — 독자불일치** | 문장의 독자가 PM 실행자가 아니라 문서 유지보수자(trainer/evaluator) | 그 독자의 문서로 이관 |

**적용 순서: G → X → S → C.** G를 먼저 걸러야 "트리거를 쓸 수 있으니 옮기자"는 논리로 승인 게이트가 새지 않는다.

**순이득 하한**: `이관 대상 블록 바이트 − pm.md에 남길 트리거 문장 바이트 ≥ 250 B`. 미달이면 잔류(트리거 한 줄이 보통 120~150 B라, 하한 없이는 옮겨도 절반이 그 자리에 남고 홉만 늘어난다).

**"상시 판정 필요"(등급판정 진입점·WBS 5조건·reviewer 풀패널 조건 등)는 S축이다.** G가 아닌 이유: 오판정 자체가 비가역은 아니다(그 뒤에 오는 승인 게이트가 G다). C가 아닌 이유: 발동 시점이 "매 작업 착수 시"라 트리거가 `항상`으로 축퇴해 이관 이득이 0이다.

## 3. 배분 규칙 (C축 블록을 어디로 보낼지)

```
C축으로 분류된 블록 하나를 받았을 때:
1) git grep -n "<블록의 핵심 문구 2~3개>" -- 'malgn-agent/skills/*' 'malgn-agent/knowledge/*' 'malgn-agent/agents/*'
2) 히트 있음  → 그 문서가 목적지다. (이미 값으로 있으면 이관이 아니라 pm.md 쪽 삭제 + 포인터 1줄)
3) 히트 없음  → 순이득 ≥ 250 B 인가?
     아니오 → pm.md 잔류. 끝.
     예     → 그때만 신설 판정(trainer 핵심 원칙의 "신설 판정")을 돌린다.
```

**이관 규율 2개** (팽창비가 라운드마다 들쭉날쭉했던 원인 — 이번엔 상수로 고정한다):
- **이식이지 재집필이 아니다**: 목적지 증가분이 이관 원문의 **1.15배를 넘으면** 이관이 아니라 신규 집필로 보고 별도 승인 사안으로 분리한다.
- **트리거는 보유하되 요약은 보유하지 않는다**: pm.md에 남기는 건 ①언제 여는가 ②무엇이 그 안에 있는가(명사구)뿐, 본문 요약은 남기지 않는다.

## 4. `project-orchestration` 2계층 구조(R-2)는 부분 해소

색인(18.5 KB)+부록(31.1 KB) 구조는 이번 라운드에서 흡수·대체하지 않는다(이관 후보 대부분이 그쪽으로 가지 않고, 검증 축이 다르다 — 색인 재구성은 외부 참조 전수 대조, 이관은 이식 충실도 대조). 대신 재발 방지 규칙만 정한다: **색인형 SKILL.md는 10 KB 이하, 절당 요약 2줄 이하.** `project-orchestration/SKILL.md`(18.5 KB)는 이 기준 위반 상태이며, 그 정리는 별도 백로그다(STATUS.md 등재).

## 5. Round A — 이번에 실행하는 범위

이동(C축 8건) + 재배치(X축 1건) + pm.md 쪽 삭제/포인터화. **트리거 슬리밍(Round B)은 포함하지 않는다** — 이동과 삭제를 한 라운드에 섞으면 reviewer가 실패 원인(이식 vs 표현강도)을 못 가린다(직전 라운드 M-2가 정확히 이 실패 패턴이었다).

| 대상(pm.md 현재 위치·문구 앵커) | 배분 규칙 적용 결과 — 목적지 | 비고 |
|---|---|---|
| 다각 토론 5단계 | `knowledge/common/cross-validation-and-collaboration.md` | pm.md가 이미 참조 중인 문서 — 흡수 |
| 다중 대상 위임 개별 검증 | `knowledge/leadership/pm-verification-field-notes.md` | 이미 참조 중 |
| 전역 승격 완료 선언 전 실사용 인터뷰 | 같은 field-notes | 주제 일치 — 착수 시 재확인 |
| 외부 UI 절차 추정 금지 | 같은 field-notes (단, `domain-product-body-authoring-rules`와 경계를 초안 시점에 재확인) | **미확인**: `git grep "외부 UI"` 4건 히트를 실제로 같은 주제인지 재검토 필요 |
| 재배치 작업 backlink 전수 검증 | `skills/reflect-lessons/SKILL.md` §4-2 | |
| 설계 착수 전 스코프 확인 | `skills/project-orchestration/delegation-transfer.md` | |

| visual-designer 투입 확인 | 삭제 후 포인터만 — 이미 `project-orchestration §3.5` + `ux-designer.md:27` + `visual-designer.md:27` 3곳에 존재(순수 중복) | `visual-designer.md:27`이 pm.md 원칙을 이름으로 인용 중 — 이관 시 함께 정정 |
| 메인 세션 행동규율과의 정합(X축) | `skills/agent-upskill` 계열의 "MD 보강" 절 | 독자가 trainer이지 PM 실행자가 아님 |

**개략 추정** (초안 이전): pm.md 40,178 B → 약 36.0~36.3 KB, 목적지 증가 약 +3.1~3.4 KB, 팽창비 약 0.8~0.9로 추정했었다.

**Round A 실측 결과(추정 교정)**: pm.md 40,178→36,976 B, 목적지 순증 +3,340 B, **팽창비 1.02**(추정 미달성). 원인은 추정이 목적지 제목줄·구분선 등 항목당 오버헤드(30~90 B)를 반영하지 못한 것 — reviewer/evaluator가 재현 확인. 이 라운드의 가치 판단 근거는 팽창비가 아니라 **상시 비용(pm.md, 매 호출 전량 로드) 감소분이 조건부 비용(invoke 시에만 로드)으로 옮겨갔다는 사실 자체**다(3영역 총합은 +57 B로 사실상 등가). 다음 이관 라운드의 추정에는 항목당 오버헤드를 반영해 팽창비 목표를 1.0 근접으로 낮춰 잡는다.

**backlink 실측(설계안 작성 시점)**: pm.md를 줄번호로 참조하는 문서 0건. 문구로 인용하는 문서 1건(`visual-designer.md:27`) — Round A 초안에서 함께 정정.

## 6. Round B — 이번 라운드 범위 밖(별도 승인 필요)

`:53`·`:54`(이미 이관 완료된 트리거의 요약 문구) 슬리밍 + `project-orchestration` 색인 크기 규칙 적용. 표현 강도 보존이 핵심 검증 축이라(`semantic-force-preservation` 페르소나 필수) Round A와 분리한다.

## 7. 함께 정정할 백로그

- **RT-001(등급별 승인 주체 값 중복, pm.md 권한표 ↔ 등급판정 스킬) — 방향 반전**: 권한표는 G축이라 pm.md에 값으로 남아야 한다. 중복 제거는 "pm.md를 축약"이 아니라 **스킬 쪽 사본을 포인터로 바꾸는 방향**이 맞다.
- **신규**: `project-orchestration/SKILL.md`(18.5 KB) 색인 크기 규칙(§4) 위반 — 정리는 별도 라운드.

## 9. 강제력 한계 (자체 인정)
