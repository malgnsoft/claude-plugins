## 1. 무엇 때문에 넘었나

이 라운드 전 22,723 B였고, `@import` 전달 채널을 폐기하고 **CLAUDE.md 인라인 관리 구역**으로 전환하면서 §9(PM 행동규율 블록 재확인/재설치)가 커졌다. 늘어난 것은 전부 **판정 절차 본문**이다:

- 상태 어휘가 4개(`legacy-no-import`/`drift`/`ambiguous`/`plugin-missing`)에서 13개로 늘었다. 인라인은 "사본이 파일 안에 산다"는 뜻이라, `@import` 시절에는 존재할 수 없던 상태(구역 손상·구역 밖 사본·버전 역전·무마커 손사본)가 실제로 생긴다. 이 상태들을 구분하지 못하면 세션이 사용자 CLAUDE.md를 잘못 덮어쓴다.
- `--write` 신설에 딸린 **거부 조건과 동의 게이트**(버전 승격 시 `--upgrade-to <n>`)가 들어왔다. 이 절차는 남의 파일을 고치는 유일한 경로이므로 문장을 줄이면 안전장치가 줄어든다.
- 역방향 전환(installed → declined) 경로가 `--decline`으로 신설됐다. 본문이 남은 채 마커만 declined가 되면 동의 위반이 되므로 생략할 수 없고, 허용/거부 상태 목록도 줄일 수 없다 — 어느 상태에서 제거 경계를 기계가 정할 수 있는지가 곧 사용자 문장을 삼키지 않는 조건이다.

## 3. 비용의 성격

**조건부 비용이다.** 이 파일은 Skill invoke 시에만 로드되며, 상시 주입되는 에이전트 MD나 `common-*` 스킬처럼 매 호출에 물리지 않는다. 발동 조건도 좁다 — 새 프로젝트 스캐폴딩, "초기화 해줘", STATUS.md 크기 검사, PM 블록 재확인. 그 네 상황에서는 이 절차 전체가 실제로 실행된다.

반대로 §9를 줄여서 생기는 비용은 **사용자 CLAUDE.md 손상**이다. 조건부 0.5 KB를 아끼려고 남의 파일을 덮어쓸 위험을 키우는 거래는 성립하지 않는다.
