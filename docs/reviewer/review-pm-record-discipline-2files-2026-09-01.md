- **강제력 감사관 vs 발산형** — 전자는 "강제 장치 0"을 문제로 보고, 후자는 "그럼에도 두 자리 개입은 비례한다"고 본다. → **권고: 발산형 손을 든다.** 유일한 강제 경로(Stop 훅)가 사용자 합의로 스코프 밖이므로, 지금 가능한 최선은 "세션 중 AI가 실제로 읽는 자리에 지시를 두는 것"이고 이번 커밋이 정확히 그것이다. 강제력 문제는 RT-2 백로그로 이월한다.
- **충돌 감사관(M2, provider 중립화) vs 발산형(상시비용)** — 폴백까지 적으면 상시비용이 는다. → **권고: 도구명 나열을 유지하되 provider 단정 표현만 중립화**(글자 수 증가 없이 처리 가능). 폴백 절차 자체는 `pm.md:46`에 이미 있으므로 훅에 복제하지 않는다.

## 잘 된 점 (다음 산출물의 기준)

- **실기동으로 도달을 증명할 수 있는 변경.** `echo '{}' | node malgn-agent/hooks/sessionstart-context.mjs --pm-block` 실행 결과에 신설 문단이 그대로 실려 나온다 — 문서만 고치고 "주입될 것이다"로 끝내지 않아도 되는 형태다.
- **하우스 스타일 준수.** 신설 문단의 "…이를 대신하지 못한다"는 바로 위 13행("리뷰·평가는 변경 이후에 오므로 이를 대신하지 못한다")과 같은 형식이고, "그 자리에서 기록한다"는 `agents/pm.md:45`·`common-learning-loop-knowledge-management/SKILL.md:35`의 확립된 표현이다. 새 어휘를 만들지 않았다.

- **번호 재배열의 상호참조까지 챙겼다.** `:116`이 새로 "(2단계 2번)"을 가리키고 그 대상이 실재한다 — 항목을 끼워넣으면서 앞단 참조를 같이 고친 것은 이 저장소가 반복해서 놓쳐온 자리다.

## PM에게 권고

1. **병합 전 처리 권고 1건**: M1(`SKILL.md:3` description 4항목 미반영). 위임이 특정한 3곳 외의 4번째 정정 사이트이며, 저장소의 "정본 고칠 때 참조처 전체 grep" 규율에 직결된다. **trainer에게 되돌려 처리**한다(reviewer는 수정하지 않았다).
2. **선택 채택 4건**: M2(provider 중립화, 글자 증가 없이 가능) · M3(트리비얼 세션 면제 한 구절) · M4(구별 근거를 "도달 범위"로 교체) · M5(②의 합격선 특정). 넷 다 실행을 막지 않으므로 M1과 묶어 한 번에 위임할지, 이번 라운드는 M1만 닫고 나머지를 백로그로 돌릴지는 PM 판단이다.
3. **RT-1·RT-2는 백로그**. 변경 동결 원칙상 구조 변경이라 이번 라운드에서 스스로 승격하지 않는다. RT-1은 "정본 4곳" 문제라 다음에 같은 영역을 만질 때 재발 비용이 커진다 — 이슈로 남길 것을 권한다.
4. **push 전 절차 알림**: 이 커밋은 `malgn-agent/` 아래를 건드렸으므로 `git push origin main` 전에 `plugin.json` + `marketplace.json` 버전업(현재 둘 다 1.8.24)과 CHANGELOG 항목을 포함한 release 커밋이 필요하다. 현재는 로컬 워크트리 상태라 위반이 아니다.
