## 요약 (2분 규칙)

**진단과 수정 방향은 옳다.** 공식문서 원문(`docs/anthropic/agents/sub-agents.md`:983)과 대조한 결과 기존 체인 `main→director(1)→autopilot(2)→PM(3)`이 PM에서 `Agent`를 잃는다는 진단은 참이고, 수정 후 체인 `main→autopilot(1)→PM(2)→전문가(3)`은 예산 안에 정확히 들어온다. director가 직접 호출하는 넷+reviewer는 전원 `Agent` 미보유라(전수 확인) 새 문제도 생기지 않는다.

**다만 재개 메커니즘의 계약이 닫히지 않았다.** director는 "목표 제목 1줄"로 hub 기록을 검색해 직전 라운드 결과를 찾는데, **그 문자열을 기록에 써 넣을 주체(autopilot)에게는 그렇게 하라는 지시가 한 줄도 없고**(`agents/autopilot.md` 전문 grep `상관|핸들|제목` → 0건), 호출자는 정상 경로에서 기록 보강이 **금지**돼 있다(SKILL 단계 3 "그대로 둔다"). 그 결과 hub 도구가 안 될 때의 **열화 경로가 정상 경로보다 튼튼한 역전**이 생겼다 — 폴백에서만 호출자가 핸들을 남기게 돼 있다(C-1). 여기에 ①깊이 복원이 "호출자=메인 대화"일 때만 성립하는데 그 전제가 두 문서 어디에도 없고(M-1) ②같은 제목이 재시도 라운드·autopilot 내부 루프마다 중복 생성되는데 어느 기록이 "그 라운드"인지 가를 규칙이 없으며(M-2) ③스킬 1종 추가로 개수 서술 4곳이 어긋나 `check-assets` ERROR 3 + `check-docs` FAIL이 났다(M-3).

## 페르소나별 관점

### [서브에이전트 런타임 제약 감사관] — 판정: 🟡 Amber
- 깊이 산수는 **맞다**. 공식문서 :983 "up to three layers below the main conversation… At the depth limit, Claude Code withholds the `Agent` tool from every subagent except a fork" — 기존 `director(1)→autopilot(2)→PM(3)`에서 PM이 한계층이라 `Agent`를 회수당한다. 수정 후 `autopilot(1)→PM(2)→전문가(3)`은 PM이 2층이라 `Agent`를 보유하고, 3층인 전문가는 애초에 `Agent` 미보유라 제약이 발현되지 않는다.
- director의 나머지 위임 경로(marketer·finance·researcher·customer-support·reviewer)는 전원 `Agent` 미보유 → **신규 문제 0건**.
- 남는 것은 전제의 미기재(M-1)와 한계값이 기본값이라는 사실의 누락(m-3)이다.

### [스킬 간 지시 충돌 감사관] — 판정: 🔴 Red
- 3자(BD·SKILL·autopilot)가 하나의 인계 배관에 각자 규칙을 명령하는데, **autopilot만 계약에서 빠져 있다.** BD와 SKILL은 상관 핸들을 전제로 쓰였고 autopilot은 그 단어를 한 번도 듣지 못했다(C-1).
- 정본 포인터는 모범적이다 — 복제 0건, 빈 포인터 0건.
- 마커 분기에서 두 문서가 다른 결론을 내는 지점 1건(m-1).

### [메커니즘 지속성 현실주의자] — 판정: 🔴 Red
- "목표 제목 1줄"은 사람이 매 라운드 손으로 옮겨야 유지되는 장치인데, 그 유지 의무가 **기록을 쓰는 주체에게는 부과되지 않았다**(C-1). 장치 설계에서 가장 먼저 스킵되는 자리다.
- 재시도·내부 루프로 같은 제목이 중복 생성되는데 선별 규칙이 없다(M-2). `project_search_history`가 `since`·`types`·`limit`를 제공하므로 도구 쪽 제약이 아니라 지시 쪽 공백이다.
- **잘 된 점**: "기록이 없으면 완료되지 않은 것으로 다룬다 — 결과를 추정하거나 지어내지 않는다"(:129)는 안전측 기본값이 정확히 옳은 자리에 있다. 이 한 줄 때문에 C-1이 오판이 아니라 정체로 끝난다.

- **런타임 제약 감사관("구조는 옳다, 전제만 명시하라")** ↔ **발산형("이 구조를 애초에 세우지 말았어야 한다")**. → **권고: 이번 라운드는 수렴형 쪽을 따른다.** 발산형 R-1·R-2는 구조 변경이라 이 저장소의 변경 동결 원칙상 보류 대상이고, 진단·방향 자체는 옳으므로 C-1/M-1/M-2/M-3만 닫아 배포 가능 상태로 만든 뒤 R-1을 백로그에 올린다. 단 R-3은 발산형 제안이면서도 결함 수정 범주라 지금 반영을 권한다.
- **지속성 현실주의자("핸들을 기계화하라")** ↔ **충돌 감사관("스킬은 최소 범위를 지켜야 하므로 배관 규칙을 더 늘리지 마라")**. → **권고: 규칙 추가 자리를 스킬이 아니라 `autopilot.md` RECORD로 잡는다.** 그러면 스킬은 지금 크기를 유지하고 계약은 정본 쪽에서 닫힌다.
