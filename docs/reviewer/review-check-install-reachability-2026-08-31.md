## 페르소나별 관점

### [스크립트-문서 정합성 감사관] — 판정: 🟡 Amber
자체보고의 **수치는 전부 실측으로 재현됐다**(ERROR 6 · WARN 25, `--repo`로 기준 트리 대조). 이 점은 높이 평가한다 — 보통 "6건 나왔다"는 주장은 재현 경로가 없어 검증이 안 되는데, architect가 `--repo` 옵션을 만들어 둔 덕에 리뷰어가 5분 만에 대조했다. 반면 **자체 픽스처는 산출물로 남지 않아 ⑤ 주장은 검증 불가**였고, 리뷰어가 직접 만든 픽스처가 곧바로 RV-001을 잡아냈다. 픽스처에 코드펜스 한 블록만 있었어도 architect 자신이 발견했을 결함이다. ④의 "4개 재현" 주장은 항목 단위로는 맞지만 **인용처 단위로는 m-10이 3곳 중 2곳**이라 과장 소지가 있다(RV-004).

### [운영 유지보수 현실주의자] — 판정: 🟡 Amber
6개월 뒤 이 파일이 어떻게 되는지가 걱정이다. `stripFencedCode`·`RETIREMENT_NOTE` 두 헬퍼가 옆 파일의 사본인데 후자는 **뜻이 정반대**다(RV-003·RV-007) — 이 저장소 `CLAUDE.md`가 명문화한 "정본 하나만 고치고 참조처를 놓쳐 왕복이 난다"는 실패 양상의 교과서적 초기 조건이다. 손유지 화이트리스트 2종(`BUNDLED_TOP` 10항목 · `USER_PROJECT_PREFIXES` 11항목)도 갱신 강제 장치가 `BUNDLE_SCOPE_DRIFT` 하나뿐인데 그마저 점 항목을 못 본다(RV-006). **잘 된 점**: 화이트리스트를 "추측이 아니라 실측으로 만든다"고 주석에 grep 명령까지 적어둔 것(`:60-63`)은 다음 사람이 갱신 방법을 알 수 있게 하는 좋은 습관이다.

### [강제력 격차 감사관] — 판정: 🟡 Amber
현재 이 검사의 강제력은 **0**이다 — `package.json` scripts에도, `.github/workflows/validate-plugin.yml`에도 없다. architect의 "지금 체이닝하면 기준선이 깨진다"는 사유는 실행으로 **참임을 확인**했다(`check-assets` 현 상태 ERROR 0, CI가 그 종료코드에 의존). 그러나 그 사실에서 "별도 npm 스크립트로 시작"이라는 결론이 자동으로 나오지는 않는다. 같은 저장소에 **선례가 있다** — `check-docs`는 워크플로 주석 71-78행에서 "편입 여부는 별도 판단"으로 남겨진 채 지금도 CI 밖이고, 아무도 돌리지 않는다. 이 검사도 같은 자리에 놓이면 다음 라운드에 "죽은 스크립트" 지적을 받는 자산이 된다. 순서는 **"배선을 미룬다"가 아니라 "ERROR 6을 수리한 뒤 배선한다"**로 읽어야 한다.

### [죽은참조 스코프 도전자 — 발산형] — 판정: 🔵 (RT-1·RT-2)
이 스크립트는 원 리뷰 R-1이 진단한 병(**"형태로 스코프를 정의해 목적 기준을 놓친다"**)의 치료제로 태어났는데, **치료제 자신이 같은 병을 앓는다.** `isJudgeablePath()`는 "확장자로 끝나거나·글로브·`/`로 끝나거나·docs 깊이3+"라는 **형태**로 판정 대상을 정하고, 여기 안 걸리는 토큰은 **아무 흔적 없이** 통과시킨다. 계측 결과 579개 토큰 중 44개가 그렇게 사라졌고 그 안에 한글 파일명 인용(RV-002)과 `skills/<스킬명>` 24회가 들어 있었다. `docs/` 화이트리스트로 면제된 178회도 마찬가지로 무음이다. 결과적으로 **"검사가 통과했다"는 신호가 "검사가 대상으로 삼지 않았다"와 구별되지 않는다** — CLAUDE.md가 경고한 "제외 항목은 괜찮다는 도장을 받고 아무도 다시 안 본다"가 코드 레벨에서 재현됐다.

## 트레이드오프 (페르소나 간 충돌)

- **강제력 감사관 vs 유지보수 현실주의자 — 배선 순서.** 전자는 "지금 배선하지 않으면 죽은 자산이 된다"며 즉시 CI 편입을 원하고, 후자는 "ERROR 6·WARN 25 중 오탐이 섞인 상태로 CI에 물리면 무시당하는 게이트가 된다"며 정제 우선을 원한다.
  → **권고: 후자 먼저, 단 기한을 붙인다.** ①RV-001·RV-003을 먼저 수리해 ERROR 6 / WARN 11(오탐 4 제거 + 비-EXEC `SOURCE_CLONE_PREFIX` 10을 INFO로 강등하면 실질 WARN 7)로 정제 → ②그 ERROR 6건(m-2·m-9)을 trainer에 위임해 실제로 0으로 만든다 → ③**ERROR 0이 된 시점에** `package.json`에 `check-links` 추가 + `validate-plugin.yml`에 스텝 추가를 같은 커밋에서 한다. ①②만 하고 ③을 "다음에"로 미루면 `check-docs`와 같은 운명이 된다.
- **정합성 감사관 vs 발산형 — 판정 범위.** 전자는 "확신 없는 토큰은 통과시킨다"는 architect 설계를 지지한다(오탐이 실탐을 덮으면 게이트가 무시당한다는 `:108-109` 논거는 타당하다). 후자는 그 통과가 무음이라 사각지대가 영구화된다고 본다.
  → **권고: 둘 다 만족하는 RT-1을 채택한다.** 판정은 지금처럼 보수적으로 두되(오탐 억제 유지), 판정하지 않은 것의 **개수만** 노출한다. 종료코드에는 영향을 주지 않으므로 게이트 신뢰도를 해치지 않는다.

## 잘 된 점 (유지할 패턴)

- **`--repo` 옵션이 리뷰 가능성을 만들었다.** 이 옵션 하나 덕에 리뷰어가 `git archive b2b1bd7`로 과거 트리를 추출해 주장을 5분 만에 재현했다. "검증 가능한 산출물"의 모범 — 앞으로 검사 스크립트에는 기본 탑재할 만하다.
- **글로브를 건너뛰지 않고 해소한 판단**(`:148-162`). "형태가 같아도 결과가 다르다"는 근거가 정확하고, 실제로 m-9(0건 글로브 3곳)를 잡는 유일한 이유다. 픽스처로 양방향(히트/0건) 확인했다.
- **실행 대상(`bin/`·`hooks/`)과 편집 대상을 `SOURCE_CLONE_PREFIX_EXEC`로 가른 것**(`:223`). 이 분리 덕에 25건 WARN 중 진짜 결함 3건이 즉시 눈에 띈다. 기계가 못 읽는 의도를 "가능성이 높은 쪽만 표시해 사람의 분류 부담을 줄인다"고 스스로 한계를 밝힌 주석도 정직하다.
- **주석이 "왜 이 조건인가"를 실측 근거와 함께 적었다** — 오탐 유형(산문 병렬표기·shebang)을 예측이 아니라 관측으로 열거하고, 화이트리스트 생성 grep까지 남겼다. 다음 유지보수자가 갱신할 수 있는 형태다.
- **자기 한계를 먼저 자백했다**(중괄호·확장자 없는 디렉터리·산문형·Windows). 이번 리뷰가 그 목록에 없는 항목(RV-002 한글 파일명, RV-004 깊이1 디렉터리)만 새로 찾으면 됐다.

1. **RV-001** 펜스를 같은 줄 수의 빈 줄로 치환 (1줄 수정) — **채택 전 필수**
2. **RV-003** `RETIREMENT_NOTE`를 `폐기` 계열 / `미번들` 계열로 분리, 후자 억제 — **채택 전 필수**(원 리뷰 판정을 뒤집는 상태로 게이트를 켤 수 없다)
3. **RV-002** 비ASCII 파일명 대응 (문자클래스 확장 또는 RT-1의 `UNJUDGED` 노출) — **채택 전 권장**. 이걸 안 하면 `skills/a4-vertical-layout/SKILL.md`의 필수 Read 지시 2건이 영구 미검증
4. RV-004·RV-005·RV-006 — 함께 처리 권장(전부 국소 수정)
5. RV-007 헬퍼 사본 — RT-2 채택 여부와 함께 판단
6. RV-009~RV-012 — 백로그

**PM이 판단할 것 (architect가 넘긴 3개 + 리뷰가 추가한 1개)**
- `FOREIGN_REPO_CITATION`을 ERROR로 올릴지 → **권고: WARN 유지.** 4건 전부 m-7 확정 결함이라 승격 근거는 있으나, 승격하면 수리 전까지 CI가 막힌다. ERROR 6 수리와 함께 처리한 뒤 승격하는 순서가 안전하다.
- `RETIRED_PATH_CITED` 존치 → **권고: 존치하되 RV-003대로 분리.** 분리 후에는 m-10의 `capture-all.js`/`capture-nav.js` 4건만 남고 그건 원 리뷰가 확정한 결함이다.
- 배선 → **권고: `check-links` 별도 스크립트 + CI 스텝을 ERROR 0 달성 시점에 같은 커밋으로.** 지금 npm 스크립트만 추가하는 것은 `check-docs`의 전철이다.
- (추가) **비-EXEC `SOURCE_CLONE_PREFIX` 10건을 기본 억제하거나 INFO로 강등할지** → 이 형태는 기존 `validate-agent-assets.mjs`가 이미 "소스 clone 편집 대상이면 정상"으로 인정한 형태다. WARN 25건 중 10건이 여기 몰려 신호를 흐린다.

**스코프 밖으로 넘긴 것 (정직 보고)**
- **Windows 실행 미검증** — 리뷰어도 macOS에서만 돌렸다. architect 자백 그대로 남아 있다.
- **`docs/reviewer/` 산출물 성격상 화면 리뷰 없음** — UI 대상이 아니므로 캡처 게이트 비해당.
- **`validate-agent-assets.mjs`(1,347줄) 전수 대조는 안 했다** — RT-2의 중복 목록은 `grep -n "REF_"` 결과와 해당 함수 3곳 정독으로 작성했고, 두 스크립트의 판정이 실제로 충돌하는지는 `REF_KNOWLEDGE_UNREACHABLE` 1건만 원문 대조했다(결과: 충돌 아님으로 기각). 나머지 `REF_*` 6종과의 정밀 대조는 RT-2를 채택할 경우 별도로 필요하다.
- **`--strict` 모드 미검증** — WARN만 있어도 exit 1이라는 코드 경로는 읽었으나 실행하지 않았다.
