# 프로젝트 관리 베스트 프랙티스

## progress.md 작성 표준

```markdown
# [프로젝트명] 진행 상황

최종 업데이트: YYYY-MM-DD HH:mm

## 상태: [진행중|완료|보류]

## 팀 구성
- [에이전트명]: [작업] → [상태] ✓/진행중/대기

## 완료된 작업
- [시간] [에이전트]: [작업 요약] → [산출물 경로]

## 다음 작업
- [에이전트]: [예정 작업]

## 결과물
- [파일 경로 목록]
```

## 상태 추적 원칙

1. **실시간 갱신**: 단계 시작/완료 시 즉시 progress.md 업데이트
2. **산출물 기록**: 생성된 파일 경로를 반드시 기록
3. **결정사항 기록**: 자율 판단한 내용은 "주요 결정사항" 섹션에 기록
4. **재작업 이력**: 피드백으로 인한 수정은 별도 기록

## 품질 검토 체크리스트

### 산출물 공통
- [ ] 파일이 실제로 생성되었는가?
- [ ] 내용이 요구사항을 충족하는가?
- [ ] 이전 단계 산출물과 일관성이 있는가?
- [ ] 한국어 표현이 자연스러운가?

### 코드 산출물
- [ ] 실행 가능한가?
- [ ] TODO/플레이스홀더가 없는가?
- [ ] 에러 처리가 포함되어 있는가?
- [ ] README에 실행 방법이 명시되어 있는가?

## 리스크 관리

### 일반적 리스크 패턴
| 리스크 | 징후 | 대응 |
|--------|------|------|
| 요구사항 모호 | 기능 설명이 1줄 미만 | 유사 서비스 표준 참고하여 자율 결정 |
| 기술 스택 불일치 | 에이전트별 다른 기술 사용 | tech-stack.md를 단일 진실의 원천으로 |
| 산출물 누락 | 설명만 출력, 파일 미생성 | 반드시 Write 도구로 파일 생성 확인 |
| 컨텍스트 소실 | 대화 길어짐 | 이전 단계 문서를 직접 Read로 다시 읽기 |

## 의사결정 프레임워크 (ADR)

모호한 요구사항을 자율 결정할 때:

```markdown
### 결정: [결정 내용]
- **배경**: 왜 결정이 필요했는가
- **선택지**: 고려한 옵션들
- **결정**: 선택한 옵션과 이유
- **영향**: 이 결정이 미치는 범위
```
